# ADR-0002：Nous 家庭記憶由本機核心管理

狀態：**已按使用者要求啟動 MEM-0 隔離實作，尚未核准產品放行**。日期：2026-10-26。基準：`ca7a8fe`。最初交付設計後，另開實作對話交付核心私有基礎，仍未接產品路徑。完整使用行為、資料欄位、接線與驗收見 [16 家庭記憶層設計](../16_Nous_Memory_Layer_Design_2026-10-26.md)，實際差異見 [MEM-0 驗證](../validation/memory-mem0-2026-10-26.md)。

## 問題與現況

Nous 的一般對話只有頁面上下文，live 通話不載入前次內容。任務與成果會保存，但沒有偏好提取與檢索。家人辨識庫只有姓名、臉部特徵及相關 metadata，辨識僅供稱呼。直接使用 Codex 後端不會接入 Codex App／CLI 的記憶。

因此記憶必須由 Nous 管理人物、來源、修改與撤銷，再向當前模型提供必要片段。模型供應商不能各自維護互不相容的家庭真相。

## 呼叫端的用法

- 當次人物已選定，使用者明確說「記住我不吃香菜」時，`memory.change` 驗證核心來源票證並持久保存，成功後才回條。
- 新對話的 adapter 用 `memory.withContext` 取本次可用片段；更正、忘記或人物切換時，由服務中止持有舊內容的輸出。
- 使用者問「你記得我什麼」時，`memory.inspect` 回傳按需清單；也用於查詢中斷前的操作結果。

`withContext` 對語音維持到整通電話結束，不在連線握手完成時釋放。模型只收到精簡資料，不能取得人物權限、來源票證或儲存格式。

## 建議形狀

採單一 `MemoryService` 作政策與寫入入口，私有 `store` 管加密、原子替換及去重。資料以一份加密快照保存，本機索引只在記憶體重建。每次寫入原子提交事實、版本、同意及不含正文的操作回條。

第一版服務單台 Mac、最多 1,000 筆普通記憶，不增加常駐資料服務。人物與臉部登記採不同 ID；口頭自我指認只用於家庭共用偏好的歸屬，不授予私密存取。

初版提供明示記住、更正、忘記與按需查看。自動整理只在後續 opt-in 批次提出候選。第一版不保存整段聊天、未喚醒音訊或原始影像。記憶資料在本機加密；允許取用時，必要片段仍會送給當前模型，傳送同意必須獨立說明。

## 方案比較與綜合決定

本次比較兩個獨立設計，再以相同模型的另一個審查席交叉核對。這是獨立設計審查，不是跨模型多樣性或效能實驗。

| 方案 | 能隱藏的複雜度 | 新增成本與限制 | 決定 |
| --- | --- | --- | --- |
| A：加密 aggregate 快照＋記憶體檢索 | 一次提交事實、回條與撤銷版本，無第二份持久索引 | 每次寫整份資料；須自行處理單寫入者、容量與失敗復原 | 首版基底 |
| B：SQLite 交易＋加密欄位＋記憶體檢索 | 多表原子修改、操作與依賴結構清楚 | runtime／Electron 打包、migration、WAL 與密文欄位政策增加驗證面 | 資料量或依賴關係確有需要時再評估 |
| 歷史提案：明文 Markdown＋FTS5 | 人可直接編輯，全文索引可重建 | 個人資料會散入正文、索引與備份，檔案與索引雙重狀態仍需一致性 | 不作首版預設；Markdown 僅明確匯出 |
| 外部記憶服務／框架 | 可提供儲存或檢索能力 | 不能代替 Nous 的人物歸屬、來源授權、通話撤銷與共享政策 | 首版不採；本次不對特定第三方版本作新結論 |

交叉審查以人物隱私、可靠修改、實際整合、MVP 體驗及維護成本各 0–4 分評估，A 為 17/20、B 為 16/20。分數是判斷記錄，沒有統計意義。選 A 的主因是現階段資料少、單寫入者與已有加密保存經驗，SQLite 的額外整合成本尚未帶來足夠收益。

從 B 納入持久操作回條查詢、撤銷版本與派生來源依賴；仍放在 A 的同一快照內，不引入第二個可寫來源。審查指出的五個問題已寫入 16 的契約：整通語音生命週期、票證綁實際命令、回條不可殘留正文、禁止模型交辦將記憶抄進明文任務、澄清卡必須有真實呈現理由。

## 接受的取捨

- 首版個人偏好是按人物分類、家中可使用的資料；每人秘密空間須另做認證。臉部校準尚未完成，不擴大其授權用途。
- 快照較容易審核，但容量上限、寫入時間與 Keychain 行為要先在目標 Mac 量測；未達標不宣稱適用更大資料量。
- 本機忘記會清理有效記憶、來源與受影響上下文，不保證抹除已送供應商的資料、已匯出檔案或 APFS／系統備份。
- API key 路徑在可靠斷線、停播與重建通過前不注入記憶，不能用 live 路徑的結果代替。
- 既有 TaskStore 為明文，首版不向背景任務注入記憶，也禁止帶記憶的模型摘要或逐字稿變成任務標題。任務記憶須等待受保護的成果儲存。
- 首版文字檢索不保證語意全召回。以中文測試集找缺口，再決定是否引入向量或 SQLite 索引。

## 歷史提案與遷移

08 的「ADR-001 記憶層」是當時待辦名稱，repo 沒有已實作的記憶 ADR；既有 `ADR-0001` 現為家人辨識。本文件使用 `ADR-0002`，避免混淆。

目前沒有舊記憶資料庫需要轉移。若未來從快照改 SQLite，先提供有版本、可驗完整性及可回復的單向遷移；確認新庫後再切唯一寫入者，不讓新舊庫同時接受修改。遷移須攜帶人物、同意、版本、刪除墓碑與操作去重資訊，不能只搬記憶正文。

本次保留 01–03、08 與 13 的歷史內容，從現況與索引連到本提案。未來採用前仍須按最新程式及測試修訂，不將本次設計視為已核准的產品能力。

## 待證明與下一步

MEM-0 先確認打包 Electron 的安全儲存介面、單寫入者復原、來源票證及兩條語音路徑的實際撤銷能力。容量已有下方隔離證據；50 ms 檢索和 300 ms 寫入仍是待測目標。

2026-10-26 MEM-0 隔離補記。已驗證打包 Electron 44.9.3 介面、快照／原生鎖、程序崩潰復原、1,000 筆容量及來源／撤銷契約。獨立打包 App 也通過真 Keychain 的加密快照與跨程序重啟讀回；正式 Nous 簽章、實際拒絕、性能與實體語音仍待驗。完整產品服務與 profile 管理介面尚未接入。操作 ID 改採帶不可變時間前綴的 UUIDv7 形狀，避免回條淘汰後同 ID 變造時間重放，理由及證據見本批紀錄。

私密記憶是否需要納入近期範圍、語音來源如何避免電視與旁人誤寫，屬後續必須收斂的產品及實機問題；首版以家庭可使用資料與疑義確認限制範圍。下一個可驗收實作是 MEM-0 後的單人物明示保存、重啟取用、更正與忘記閉環。
