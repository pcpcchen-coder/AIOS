# Pi 終端改用藍牙連 eMeet M0 Plus：規劃（RPI-BT，未實作）

日期：2026-11-07。狀態：**只有規劃，沒有程式，也沒有實測**。George 2026-11-07 決定先用文件記錄，以後再做。

## 背景

- 目前 Pi 4 終端用 USB 線接 eMeet M0 Plus（麥克風＋喇叭），運作正常。George 之後要改用藍牙。
- M0 Plus 沒有附 USB 藍牙接收器，所以要走 Pi 4 內建藍牙。
- 程式已經能處理「選定的喇叭中斷時改用系統預設、接回後換回來」（`src/audio-devices.ts`），但沒有在 Pi 上用藍牙驗證過。

## 最關鍵的限制

- 藍牙要同時用麥克風與喇叭，只能用「通話模式」（HFP）。收音與播放都會降到電話音質：
  - 寬頻（mSBC，16 kHz）：一般對話可用；
  - 窄頻（CVSD，8 kHz）：聲音明顯變差。
- **M0 Plus 在藍牙下支援哪一種，目前不知道**，要在 Pi 上實測，不能先假設。
- 可能的影響：喚醒詞「Hello Nous」與聲紋辨識的準確度下降。之前已經遇過換麥克風後聲紋認不出來（見 [Pi 部署實機紀錄](../validation/rpi-deployment-fixes-2026-11-05.md)），換藍牙後大概要在藍牙收音下重新登記聲紋。
- 藍牙會多出約 0.1～0.2 秒延遲（估計，未量測）。
- Pi 4 的藍牙與 Wi-Fi 共用同一顆晶片，所以網路維持有線。

## 預計要做的事（Pi 終端套件 `terminals/rpi4/`）

1. **配對腳本 `aios-bt-pair`**
   - 用 `bluetoothctl` 配對 M0 Plus，並設為信任，讓開機後自動重連。
   - 把它固定在通話模式，確保麥克風可用。
   - M0 Plus 怎麼進入配對模式，等實作時照產品說明書寫，不憑記憶猜。
2. **`aios-doctor` 加三項檢查**，照現有 PASS／WARN／FAIL 寫法：
   - eMeet 藍牙有沒有連上；
   - 目前是不是能收音的通話模式；
   - 用的是寬頻還是窄頻（窄頻為 WARN）。
3. **開機自動重連**：需要時加一個小的 user service。
4. **退回有線**：結果不好就插回 USB，套件改用有線，不需要重裝。`uninstall.sh` 要能移除藍牙相關設定。
5. **中英文件**：安裝、疑難排解與下面的實測清單。dry-run 測試加上假的 `bluetoothctl`／`wpctl`。

## 實測清單（做的時候才跑）

- 記錄：Pi OS 版本、音訊系統（PipeWire／WirePlumber 版本）、實際編碼（mSBC 或 CVSD）。
- 30 分鐘即時語音對話：記錄斷音次數與首次回應延遲。
- 斷線與重連：關掉 eMeet 再打開三次，看多久恢復、頁面是否跳回原裝置。
- 喚醒詞：在藍牙收音下，20 次正例、20 句負例，記錄命中與誤觸發；和有線結果比較。
- 聲紋：先備份加密家人資料，用藍牙收音重新登記並試認。
- 對話音量（VOL-1／VOL-2）在藍牙喇叭下是否照常。
- 每一項明確記成 PASS／FAIL／NOT SUPPORTED。

## 何時算可以正式換藍牙

上面的 30 分鐘對話沒有持續斷音，喚醒詞命中率不明顯低於有線，而且聲紋重新登記後能認出人。任一項不行就維持有線，並把結果寫進這份文件。
