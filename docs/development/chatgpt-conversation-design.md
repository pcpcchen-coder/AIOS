# 電子腦 ChatGPT 對話設計

這份文件記錄 2026-10-20 的瀏覽器 STT、文字串流與 TTS 對話批次。後續已加入 API key Realtime 與 Codex live 兩條即時語音路徑，不能以本文件推斷最新語音功能或其驗收狀態。最新現況見 [目前實作狀態](../Current_Implementation_Status.md)，後續方向見 [功能擴充評估](../13_Feature_Expansion_Assessment_2026-10-24.md)，語音證據見 [2026-10-23 即時語音驗證](../validation/live-voice-2026-10-23.md)。

Continue with ChatGPT 文字引擎與 Codex 即時語音使用不同登入流程。前者的真實授權與推論未驗證；後者有家中 Mac 的局部登入與通話 log，以及修正後查溫度的口頭成功回報，尚無完整端到端或計費驗收。以下保留當時的設計與測試涵蓋範圍。

## 需求與範圍

使用者透過電子腦與自己登入的 ChatGPT 帳號對話。語音為主要入口，可隨時插話，文字作為同一段對話的備援。電子腦維持主要視覺，登入、設定與回覆只在需要時呈現。

本批次延伸 `prototype/ambient-shell`，沿用既有帳號登入、`/api/chat` 串流及背景任務。語音使用瀏覽器辨識與電腦播報。真實 ChatGPT 帳號授權、模型回覆及實體麥克風、喇叭須分別驗證。

## 使用方式

點擊電子腦或明確啟動對話。需要登入時顯示現有 ChatGPT 設定。登入後，由使用者再次啟動語音並同意收音。OAuth 回呼不自動啟動麥克風。

語音與文字都呼叫同一個 `ConversationSession.send`。停用或拒絕麥克風後，文字仍接續同一段歷史。插話會中止當前生成與播報。關閉對話會停止前景收音、生成與播報，既有背景任務仍繼續執行。

## 狀態與責任

`src/conversation.ts` 是對話歷史、當前回覆、取消與可見性的唯一擁有者。歷史以使用者及助理訊息成對保留，送出前依 UTF-8 位元組數移除最舊的完整回合。主程式只連接輸入、帳號設定、視圖與音訊。

新回合開始前，先讓舊回合失效，再取消傳輸與音訊。所有非同步回呼都必須屬於目前回合。中斷時可保留已收到且標示中斷的部分回覆，舊請求的結束處理不再追加歷史。切換引擎或帳號會清除舊對話。歷史只保留於頁面記憶體，重新整理或登出也會清除。這和 `data/` 內持久化的任務與成果不同。

`VoiceConversation` 保持音訊裝置的責任。電子腦的對話狀態從有效收音、等待模型及實際語音播放事件推導。排入 TTS 佇列不等於已開始播放。背景任務的進度比例另由既有任務狀態計算。

當前回覆附有真實 `request_id` 與 `visibility_reason=user_request`。收起後的晚到片段不能重新展開畫面。設定、進度與成果視圖沿用既有 Shell 與 Presentation Policy。

串流必須收到完成或錯誤事件才結束。提早 EOF 及模型的 `response.incomplete` 都顯示失敗或不完整狀態，不能當作完成。

## 設計比較與選擇

兩個獨立設計都選擇單一對話模組。審查者與主實作者沿用同一模型，這次比較不代表跨模型共識。

| 方案 | 核心結構 | 取捨 |
| --- | --- | --- |
| A，採用 | 一個管理回合與副作用的 `ConversationSession` | 小介面直接收斂歷史、取消與串流責任。 |
| B | 同一個 session 加上內部事件轉移函式 | 較明確描述事件，但這個規模不需要額外轉移層。 |

採用 A，加入 B 的兩個具體限制：登入後仍需明確啟動麥克風，開啟其他本機視圖時抑制舊對話。保留原有 Shell reducer，避免把背景任務與短暫對話混成同一個狀態機。

這是 pstack 的 Model the Domain 與 Laziness Protocol 原則在本批次的選擇。驗證依 Prove It Works 原則分開記錄單元測試、真實建置頁面的瀏覽器操作、模擬外部服務及尚未完成的帳號與硬體實測。
