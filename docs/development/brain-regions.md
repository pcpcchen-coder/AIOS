# 擴充電子腦功能區

這份文件保留六腦區合併批次的設計與驗證範圍。當時的語音說明主要是瀏覽器 STT、文字串流與 TTS；後續即時語音與鏡頭互動的實作不由這份歷史紀錄驗收。最新範圍見 [目前實作狀態](../Current_Implementation_Status.md)、[即時語音驗證](../validation/live-voice-2026-10-23.md) 與 [功能擴充評估](../13_Feature_Expansion_Assessment_2026-10-24.md)。

這個批次合併 `claude/blissful-rubin-rbtgtk` 的 `17147ef`，保留既有 ChatGPT 語音與文字對話，並將原本語言、數理、藝術三區擴充為六區，增加聽覺、視覺與規劃。

## 判讀動畫

腦區亮起代表目前的應用活動或內容分類。畫面同時說明來源，例如「視覺區・主題分類」、「聽覺區・麥克風收音」或模擬任務步驟。這不是模型內部神經活動，也不代表原型具備完整的人類感官。

任務規劃階段點亮規劃區。後續依目前執行步驟的 `domain` 呈現。不同背景任務可同時啟動不同區域，終止任務不再貢獻活動。

語音與文字共用同一個 `ConversationSession`。只有目前有效且正在等待回覆的對話會提供主題活動。回覆完成後，若電腦語音仍在播放，語言區可繼續反映實際播報。收音另由瀏覽器音訊開始與結束事件決定，不從輸入框開啟或語音模式開關推測。

視覺區可以呈現影像相關的對話主題。沒有攝影機串流或影像分析時，不顯示成正在觀看。未知主題可維持中性，不必為了動畫而硬套分類。後續鏡頭管線提供在場、頭部面向、手掌停止與手臂指向事件，仍不是眼睛視線追蹤；距離使用標稱雙目參數，尚未經完整實機校正。這些事件也不能宣稱模型正在理解鏡頭內容。

## 維持一份設定

六個領域的識別值、名稱、配色及分類資訊集中在 `prototype/ambient-shell/shared/domain.ts`。模型規劃的 enum、提示詞及前端顯示從這份設定取得。

活動從對話、任務和音訊各自擁有的狀態推導。沒有第二份 `chatDomain` 或獨立活動生命週期。這是 Model the Domain 原則在本次合併的選擇，用單一設定與具來源的活動資料取代散落的條件判斷。

設計比較採用集中設定加純狀態投影，加入實際音訊事件及模擬來源標示。沒有加入通用活動儲存庫或多主題分析引擎；並行任務、對話與音訊本身已能表達多區活動。

## 驗證來源

從儲存庫根目錄執行 `node scripts/verify-aios.mjs`，檢查型別、測試、建置與隔離的模擬 HTTP 流程。瀏覽器驗證操作真正建置頁面，只在帳號、模型及音訊服務邊界使用 fixture。截圖與報告必須註明模擬範圍，不能用來宣稱真實帳號、麥克風、喇叭或攝影機已驗證。

已安裝 Playwright 與 Chromium 時，執行 `node scripts/verify-regions-browser.mjs --output /tmp/aios-region-verification`。可用 `PLAYWRIGHT_MODULE` 與 `CHROMIUM_PATH` 指定現有安裝位置。驗證前先建置原型，執行期間不要修改來源或重新建置，讓報告中的來源與資產雜湊對應同一個版本。
