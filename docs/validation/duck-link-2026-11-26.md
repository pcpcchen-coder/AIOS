# DUCK-1 鴨子（duck-link 端點、duck adapter、互動狀態）驗證

日期：2026-11-26，Asia/Taipei。分支：`claude/duck-link`（基於 main `c853078`）。範圍：讓 Nous 能使用一隻會動的機器鴨（[Nous Duck](https://github.com/pcpcchen-coder/Open_Duck_Mini)，Open Duck Mini v2 的 fork）：核心新增 `/duck-link` WebSocket 端點、`duck` adapter（`app.duck.*`），以及由即時語音工作階段的真實事件驅動的鴨子互動狀態（presence）。

**這不是實機驗收，也不是真實語音驗收。** 全部是 fixture 測試（標示 mock 的假鴨子）加上一次對鴨子端程式 `duckd` 的**模擬身體**的本機檢查。沒有任何一項在真的鴨子上跑過，也沒有用真的即時語音叫過鴨子。旗標 `NOUS_DUCK` 預設關閉；關閉時行為和這個批次之前相同。

## 1. 做了什麼

| 批次 | 內容 | 檔案 |
|---|---|---|
| D1 | `/duck-link` 端點：核心的 http server 多接一條 WebSocket 升級。鴨子是 client（經 SSH 通道連到核心的 loopback）；雙方先送 `hello`，核心每 500 ms 送心跳（連線租約）並量往返時間；指令與 `ack` 配對；保存最新 `state`；雙向訊息都用 duck-link v0 的 JSON Schema 驗證 | `server/duck/link.ts`、`server/duck/schema.ts`、`shared/duck-link.ts`、`shared/duck-link.v0.schema.json`、`server/nous.ts`、`server/config.ts` |
| D2 | `duck` adapter：17 個 `app.duck.*` 工具的定義都在，**第一階段只啟用 6 個**：`status`、`stop`、`look`、`gesture`、`express`、`track`。其餘 11 個（走路、導航、回充等）`enabled: false`，不出現在模型的工具表，也不列在指令表 | `server/integrations/adapters/duck.ts`、`server/duck/exec.ts`、`server/duck/text.ts`、`shared/duck-capabilities.ts`、`server/integrations/index.ts`、`server/integrations/catalog.ts`、`server/messages.en.json` |
| D4a | 工作階段觀察點：`RealtimeSessions` 新增選用的 `onSessionEvent`（決定開始、連上、live 的委派、結束）；核心把這些事件轉成鴨子的 presence（`wake`／`thinking`／`listening`／`working`／`error`／`idle`），去抖動後經 duck-link 送出 | `server/realtime-routes.ts`、`server/app.ts`、`server/duck/session-bridge.ts`、`server/duck/presence.ts`、`server/nous.ts` |

結果語意和其他 adapter 相同：鴨子接受而且之後讀回的 `state` 符合才是 `confirmed`（動作類只代表「已接受並開始」，不是做完）；接受但沒有回讀是 `unconfirmed`；送出後沒有回覆或連線中斷是 `unknown`；鴨子拒絕、參數不對或鴨子自己回報沒有這項能力是 `refused`（鴨子的原因代碼在 `data.duck_reason`）；沒有連線、沒有送出是 `failed`。對面是模擬的鴨子時，訊息以「（模擬）」開頭、`data.mock` 為 true，整合狀態的 `mock` 也是 true。

安全界線：Nous 只下意圖（頭部目標姿態、動作名稱、表情名稱）。夾限、跌倒、過熱、緊急停止與連線租約都在鴨子本機判斷；協定裡沒有關扭力、重開機、解除緊急停止這類操作，核心也送不出 schema 沒有的指令（有測試）。

## 2. 旗標、啟用與回退

| 設定 | 預設 | 作用 |
|---|---|---|
| `NOUS_DUCK=on` | 關閉 | 建立 duck-link hub、在核心的 http server 接 `/duck-link` 的升級、把工作階段事件接到鴨子的 presence |
| `NOUS_AIL=on`＋`NOUS_AIL_SERVICES` 含 `duck` | 關閉 | 註冊 `duck` adapter，模型才看得到那 6 個工具。只列 `duck` 而沒有 `NOUS_DUCK=on` 時不註冊，log 會寫出原因 |

- 關閉時：沒有 hub、沒有 `upgrade` 監聽（`/duck-link` 的升級和以前一樣被關掉）、`RealtimeSessions` 沒有觀察者、沒有 duck adapter。`tests/duck-core.test.ts` 與 `tests/duck-presence.test.ts` 各有一項確認這一點。
- 回退：把 `.env` 的 `NOUS_DUCK` 拿掉（或設成 `off`）並把 `duck` 從 `NOUS_AIL_SERVICES` 拿掉，重新啟動 Nous。沒有寫入任何設定檔或資料檔，不需要清理。
- 沒有密碼或金鑰要設定。信任邊界和 Raspberry Pi 終端相同：核心只聽 `127.0.0.1`，鴨子經 SSH 通道進來。`/duck-link` 另外做了：路徑必須完全相同、`Host` 必須是核心自己的埠、**帶 `Origin` 的請求一律拒絕**（瀏覽器頁面不能冒充鴨子）、單則訊息上限 64 KiB、同一時間只有一條鴨子連線、3 秒沒有任何訊息就關閉。Pi 上能連到通道那個埠的程式都能冒充鴨子——這和 Pi 終端的現況一樣，沒有另外的裝置驗證。

通道（擇一；Pi 本機的埠必須等於核心的埠，否則過不了 `Host` 檢查）：

```bash
# Mac 發起（不必開 Mac 的「遠端登入」）
ssh -N -R 127.0.0.1:8787:127.0.0.1:8787 <鴨子的主機>
# 或沿用 terminals/rpi4 的作法：Pi 發起 -L 127.0.0.1:8787:127.0.0.1:8787
```

注意：這條通道把核心整個 HTTP API 都開給鴨子那台 Pi 上的程式（Pi 終端本來就是這樣）。

## 4. 沒有驗證的事

- 真的鴨子：任何實機動作。鴨子端的實機頭部測試在 Nous Duck repo 進行。
- 真實即時語音：沒有啟動會連雲端模型的 Nous，沒有用語音叫過鴨子；模型實際怎麼使用這 6 個工具沒有看過。
- presence 的節奏（去抖動 120 ms、`wake` 至少 600 ms、`error` 1.5 秒）沒有對著真的對話與真的鴨子調過。
- 核心只知道工作階段的開始、連上、委派與結束，**不知道模型正在說話**：連上之後鴨子一律是 `listening`，沒有 `speaking`。準確的聽／想／說要頁面回報 phase，是之後的批次。
- 長時間連線、Wi-Fi 變差、Mac 睡眠後恢復。
- macOS App（Electron）裡的行為：只在終端機版（`startNous`）的測試裡跑過。

## 5. 使用者要怎麼試（不影響正在跑的 Nous）

以下步驟**沒有人執行過**（會連雲端模型、會出聲，要你自己啟動）。作法是另起一個開發實例，用不同的埠與設定目錄，不動正在跑的 Nous。

1. 在這個分支的 checkout：`cd prototype/ambient-shell && npm ci`。
2. 在 `prototype/ambient-shell/.env`（終端機版讀這個檔；不要改 macOS App 的 `.env`）寫入：

   ```bash
   PORT=8790
   NOUS_CONFIG_DIR=<一個新的空資料夾，例如 ~/.config/nous-duck-dev>
   NOUS_OAUTH_PORT=1456
   NOUS_DUCK=on
   NOUS_AIL=on
   NOUS_AIL_SERVICES=duck
   ```

   即時語音需要的登入或 API key 由你自己照 [INSTALL](../../prototype/ambient-shell/INSTALL.md) 設定（新的設定目錄是空的，登入狀態不會沿用正在跑的那一份）。
3. `npm start`，用瀏覽器開 <http://localhost:8790>。log 應該有一行「鴨子：duck-link 已開在 ws://127.0.0.1:8790/duck-link」。
4. 開通道並讓鴨子連過來（埠要和上面一致）：`ssh -N -R 127.0.0.1:8790:127.0.0.1:8790 <鴨子的主機>`，鴨子端的 `duckd` 連 `ws://127.0.0.1:8790/duck-link`。log 出現「鴨子：鴨子已連線」；設定頁的整合狀態會顯示鴨子（對面是模擬身體時標示模擬）。
5. 開始即時語音，說「鴨子看左邊」「鴨子點點頭」「鴨子停」。開始與結束對話時鴨子應該有反應（presence）。
6. 結束：關掉 `npm start` 與通道。要回到沒有鴨子的狀態，把 `.env` 的 `NOUS_DUCK` 與 `NOUS_AIL_SERVICES` 的 `duck` 拿掉。

還不確定的地方：`NOUS_OAUTH_PORT` 換成 1456 之後 ChatGPT 登入是否正常沒有試過（用 API key 路徑就不經過它）；兩個 Nous 同時開著即時語音時彼此不知道對方存在。

## 6. 依賴

新增 `ajv` 8.20.0（JSON Schema draft 2020-12 驗證器，只在核心用，不進頁面的 bundle）。整合層原本刻意不加依賴（`server/integrations/schema.ts`）；這裡加它是因為 duck-link 的契約是另一個 repo 的 JSON Schema 檔，兩端要用同一份檔案驗證，手寫驗證器會和 schema 走鐘。
