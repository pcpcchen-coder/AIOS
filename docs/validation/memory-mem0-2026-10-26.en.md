`MemoryStore` has no HTTP, model, or person-authorization concept and must not be exposed directly to the renderer. MEM-1 MemoryService must verify sources before calling it. `read()` is core-only too; never give models full snapshots or deduplication keys.

Snapshots use a fresh DEK and nonce for each update, AES-256-GCM, and AAD bound to format, version, and wrapped key. Only ciphertext enters temporary files. Save order is file fsync, rename, directory fsync, then in-memory update and success. Data and body-free receipts share one ciphertext. Unlock failure, corruption, wrong permissions, or write failure never falls back to plaintext or overwrites the store as empty.

Single-writer enforcement uses macOS `/usr/bin/lockf` to acquire a BSD lock on a Node-inherited fd, continuously held by the core. The lock file is not deleted, avoiding racy PID-based stale-lock cleanup. A second real Node process was refused; OS released the lock after SIGKILL of the owning core. This implementation currently supports macOS only; other platforms are disabled. File locks are not a security boundary against malicious tampering by the same OS user.

Receipts are capped at 2,048. Fingerprints use HMAC with a snapshot-private key, retaining neither original phrases nor bare hashes vulnerable to direct dictionary matching. Review demonstrated that a floor based only on caller time allowed replay of evicted IDs with altered timestamps. Core now generates UUIDv7-shaped IDs whose 48-bit time must equal `issuedAt`, retaining 74 random bits. The floor rejects original evicted IDs. If many operations in the same millisecond were evicted, other uncommitted operations in that millisecond are conservatively rejected too; a new direct input must create a new operation. MEM-1 must consistently use `newStoreOperation`; models cannot choose IDs or times.

Comparing two source designs led to WeakMap opaque objects, without wire bearer tokens. JSON, clones, other services, and restarts cannot manufacture the same capability. Source tickets bind core-observed input, session, person generation, sequence, expiry, and complete command. MEM-0 accepts only exact isolated syntax `記住：內容`, `更正：id@revision：內容`, and `忘記：id@revision`; this is not natural-language understanding. Voice sources, trusted main-window input, and confirmation cards still need MEM-1/MEM-2 wiring and acceptance. Model/document `source: user` is not authority.

`withVoiceContext` releases only after the adapter's `closed` promise; handshake completion does not end the lease. Revocation synchronously blocks delivery, installs a shared barrier, aborts, then awaits once-only cleanup. Pending handshakes are inside the barrier. Timeout can only report failure; late-established connections are still cleaned up. Connection/call failure must also clean up; cleanup failure or timeout disables the path and cannot report complete revocation success. Production `live` and `api_key` are always rejected by this module. No existing voice path was changed or received memory injection.
