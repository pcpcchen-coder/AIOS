# AIL-1 App Integration Layer 共用層驗證

日期：2026-11-03（Asia/Taipei）。分支：`claude/ail-1-registry`，從 `design/app-integration-spotify-2026-11` 開出（main `6674cec` 加上 George 的設計文件）。範圍是 [18 §6](../18_App_Integration_Layer_and_Spotify_2026-11.md) 的 AIL-1。

**本批不連任何真實 App。** 唯一註冊的 Adapter 是模擬的 `mock`。Spotify 沒有任何工具：Registry 拒絕註冊所有 `app.spotify.*` 工具（SP-2 BLOCKED）。以下測試都在 Linux 雲端容器用 fixture 執行（假 Codex、假頁面、假即時語音路徑、mock Adapter），**不是 Mac，也不是真實語音**。

## 1. 交付內容

路徑都在 `prototype/ambient-shell/`。

| 檔案 | 內容 |
|---|---|
| `shared/integrations.ts`（新） | `EffectClass`、`IntegrationRoute`（api_key／live／text／background）、`CapabilityStatus`；統一 `ToolResult`，`ok` 一律由 `status` 推導，只有 `confirmed` 為 true；固定的原因代碼；工具 ID `app.<service>.<action>` 與模型看到的函式名稱 `app__<service>__<action>`，兩者可逆；按需狀態的型別 |
| `server/integrations/contracts.ts`（新） | `IntegrationAdapter`、`ToolDefinition`（含 `supportedRoutes`、`timeoutMs`）、`ExecutionContext`（含 request-id 與中止訊號） |
| `server/integrations/schema.ts`（新） | 不加新依賴的 Schema 子集：註冊時檢查 Adapter 的 Schema，呼叫時驗證模型的參數。只接受平面物件、限定型別、`additionalProperties:false`；錯誤訊息不回顯參數值 |
| `server/integrations/registry.ts`（新） | 檢查重複 ID、Schema、版本、服務歸屬、時限（100 ms–60 s）與路徑。工具清單由三個條件決定：核心設定啟用該 Adapter、工具本身啟用、路徑有支援。定義在註冊時複製並凍結；Registry 沒有任何「啟用」方法 |
| `server/integrations/policy.ts`（新） | `SPOTIFY_VOICE_CONTROL_GATE = "blocked"`：任何 `app.spotify.*` 註冊都拒絕；`external_commit` 一律要確認；每個 Adapter 每分鐘 30 次；結果 data 上限 4 KB |
| `server/integrations/dispatcher.ts`（新） | 拒絕順序：未註冊、停用、路徑不支援、參數不對、需要確認（本批沒有確認卡，一律拒絕）、超過頻率。逾時或中止回 `unknown`；Adapter 丟錯時 read 回 `failed`，有副作用回 `unknown`；結果不符契約回 `failed`。稽核只記 request-id、工具、Adapter、effect、路徑、status、毫秒 |
| `server/integrations/status.ts`（新） | 按需健康檢查（3 秒時限，5 秒快取，不在背景輪詢）。逾時、丟錯、或回報不一致時一律 `unknown`；Adapter 沒有啟用時是 `not_configured`，而且不會去檢查它 |
| `server/integrations/adapters/mock.ts`（新） | `app.mock.echo`（read）、`app.mock.toggle`（reversible_write），說明與結果都標「模擬」 |
| `server/integrations/index.ts`（新） | `createIntegrations`：`NOUS_AIL` 關閉時回 null；`NOUS_AIL_SERVICES` 只能從已審核清單選，其他名稱略過並記 log |
| `server/config.ts` | `NOUS_AIL`（預設 off）、`NOUS_AIL_SERVICES` |
| `server/realtime.ts` | `RealtimeCapabilities.integrations`：整合工具接在家電／記憶工具之後、MCP 之前；有工具時才加一段 `INTEGRATION_RULE` |
| `server/live-tool-caller.ts` | ChatGPT 方案路徑：`app__` 工具在核心由 Dispatcher 執行，不經頁面，和頁面工具共用 `maxHostCalls`。結果不明而模型又沒說話時，回「結果不明，請確認」，不說「處理好了」 |
| `server/app.ts`、`shared/types.ts` | 只有旗標開啟時才有：`GET /api/integrations/status`、`POST /api/integrations/call`（驗 session_id＋owner，只限 API key 路徑的工作階段，路徑由核心決定）、settings 的 `integrations.tools` |
| `src/realtime-tools.ts`、`src/realtime.ts`、`src/main.ts`、`src/api.ts` | API key 路徑：頁面收到核心列出的 `app__` 名稱時轉交核心，只顯示核心回的固定句；轉交本身失敗時回 `unknown` |
| `server/nous.ts` | 組裝整合層並接到兩條路徑 |
| `server/messages.en.json` | 新增的固定句英文版 |

|---|---|
| 重複 tool id、非法 schema | 通過：重複 Adapter 或工具、14 種不合法定義都整個拒絕，不留下部分註冊 |

| 不同路徑相同語意 | 通過：同一個工具在 api_key 與 live 上的名稱與 parameters 完全相同 |

| token 不出現在 log | 通過（本批沒有權杖）：稽核欄位固定，不含參數與 data；Adapter 額外塞的欄位會被丟掉 |

| 斷線 | 部分：頁面轉交失敗回 `unknown`。真實服務斷線留給 SP-1 |
| 確認卡一次性 | **未做**：本批沒有接確認卡，`external_commit` 一律拒絕、不執行 |
| HomeBridge 不退化 | 通過：既有測試全部通過，家電程式沒有改動 |
| 旗標關閉逐位元組相同 | 通過：3 組能力 × 2 種語言，`integrations` 沒提供和提供空清單時，工具表 JSON、規則、兩條路徑的說明完全相同；HTTP 路由 404、settings 沒有 `integrations` |

## 3. 限制與未完成

- 沒有真實 App、真實語音或 Mac 驗證。`mock` 只證明整合層本身的行為。
- `external_commit` 還沒有接確認卡（沿用 ApprovalQueue 留到之後的批次），目前一律拒絕。
- 頁面轉交失敗時，即使是 read 工具也回 `unknown`（保守做法）。
- `text`、`background` 兩種路徑只列在契約上，沒有接上任何呼叫端。
- API key 路徑的整合工具不會點亮腦區（目前的腦區來源是任務步驟與對話主題，本批沒有加新的事件來源）。
- 已知但沒有修的既有行為：ChatGPT 方案路徑上，頁面工具（例如 `home_control`）結果不明、模型又沒說話時，仍會說「處理好了，但沒有可以轉述的結果」。本批只修了整合工具，沒有改家電路徑。
