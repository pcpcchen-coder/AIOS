# WK-01a always-on wake listening foundation validation

Date: 2026-10-31, Asia/Taipei. Branch: `claude/wk-01` (based on main `9778b41`, not yet committed or merged). Scope: WK-01a in [plan 17 §13.4](../17_Wake_Word_and_Speaker_Recognition_Plan_2026-10.en.md#134-交付批次與估時) (split out of WK-01 per [17 §14.1](../17_Wake_Word_and_Speaker_Recognition_Plan_2026-10.en.md#141-2026-10-31-的分批決定wk-01)). Rules are in [ADR-0003](../adr/ADR-0003-local-wake-and-voice-recognition.en.md).

**This is not hardware acceptance, and there is no real wake detection.** This batch delivers only the always-on wake listening foundation and wiring. Without an engine, the product detector honestly reports `runtime_missing`, never opens the microphone, and never detects. All tests below ran in a cloud container with fixtures (fake MediaDevices, fake capture graph, fake detector, fake earcon) and fake clocks — **not a Mac, not a microphone, and not the wake word**. None of W1–W12 in plan 17 §13.2 ran on the Mac.

<a id="3-設計選擇"></a>
## 3. Design choices

1. **Byte-identical with the flag off**: the snapshots in `tests/wake-flag-off.test.ts` were created at base `9778b41`, before any wake code, and the later changes did not update them: `pageHeaders(false / true)`, the served page headers, the `GET /api/settings` response body, and the menu bar template are all identical. The only deliberate change is that `/wake-runtime/` moves from the SPA fallback (200 with index.html) to 404.
2. **State follows device events**: `armed` means only that the microphone is being acquired; `listening_local` comes only after the track is `live`, the capture graph is connected, and the worker has processed the first chunk (`started`).
3. **The one-time resume caption** shows only after a successful automatic resume (the preference was on at App start, or return from sleep or lock). If the main window is not visible, it shows once when `visibilitychange` reports visible. Turning the switch on from the menu uses the default microphone, shows no resume caption, and records the device that actually listened.
4. **Pause lasts only for the current run**: it lives in page memory, is never written to `wake.json`, and a return from sleep or lock does not resume while paused.
5. **No retries on errors**: `device_missing`, `device_ended`, `permission_denied`, and `runtime_missing` stay in `error`. Only a user action or a system event (switch, resume, wake, unlock, end of Web Speech, end of a call) tries once more; no other microphone is used.
6. **The trigger end point**: detection → guard → earcon → not cancelled and still `listening_local` → `onTrigger(WakeTrigger)`. By default it only shows the caption 「聽到了」 and keeps listening, without opening a call. WK-02 interfaces: `WakeController.setTriggerHandler`, `lease()` / `releaseLease()`, `NoVoiceWatchdog`, `power()`, `webSpeech()`.
7. **The no-voice timer is an energy threshold, not a VAD**: `NoVoiceWatchdog` reuses the RMS threshold of the realtime early-speech detector (0.03 sustained for 300 ms, uncalibrated) and cannot tell voices from TV, music, or a closing door. WK-02 wires it into calls.
8. **The auditory region does not react**: region activity still takes capture only from the three voice modes; the small microphone icon is a separate DOM element hidden outside `listening_local`.

<a id="4-與規劃不同之處"></a>
## 4. Differences from the plan

- “Only `front-end.ts` calls `getUserMedia({ audio })`” holds with the flag on. With the flag off, the original `browserRealtimeDeps().getMicrophone` (`src/realtime.ts:891`) stays as required, so the static test pins that single line; the camera pipeline's `getUserMedia` uses `audio: false`.
- The worker file is `wake-worker.ts` (not `kws-worker.ts` from 17 §12), so no build artifact name contains kws (`tests/wake-privacy.test.ts` would block it).
- The menu bar states, reasons, and copy exist once in `desktop/settings-menu.mjs` and once in `desktop/preload.cjs` (the App runs these files directly and cannot load `.ts`); tests check that both match `shared/wake.ts` exactly.
- `device_id` is cleared when the switch is turned off: the next explicit enable uses the default microphone. If the preference is on at App start but no device was ever recorded (it never actually listened), the default microphone is used.

<a id="7-風險與限制"></a>
## 7. Risks and limitations

- **No real detection**: nothing in WK-01a is evidence of wake capability; W5 and W6 need WK-01b and the Mac living room.
- **Renderer code can still read the microphone**: as in ADR-0003 §2.3 item 3; static tests only block literal patterns.
- **The switch lives only in the main process** (review fix M2): `POST /api/settings/wake` always answers 403 to `wake_listen: true`, and the page can only record `device_id` or turn listening off. Turning it on is possible only from the App main process after the native explanation, through `NousHandle.wake.setListen` (same process, not over HTTP, no preload API). The browser version therefore cannot turn always-on listening on. `POST /api/settings/camera` has the same class of issue (page scripts can turn the camera on); it is tracked as a separate known item and not changed in this batch.
- **Switching straight from voice mode to realtime voice** (review fix m5): the reclaim after Web Speech ends is deferred to the next macrotask, and a lease arriving in the same tick cancels it, so two `getUserMedia` calls are no longer pending at once; still observe W8 on the Mac.
- **Background AudioWorklet and earcon autoplay** are unverified in Electron; `capture.ts` connects the worklet to a zero-gain output so that it keeps being scheduled, and whether that is needed also awaits the Mac.
- **Reloading the page** forgets “Pause listening” (it lives in page memory) and is treated as an App start, so listening resumes automatically.
- `NoVoiceWatchdog` is an energy threshold, not a VAD; with the TV on it may never time out.
- The 1.5-second speech tail, 3-second de-duplication, 350 ms earcon, and RMS threshold are uncalibrated starting values.

## 8. Fixes after the independent review (2026-10-31)

The independent review found no blockers, 2 majors, 9 minors, and some nits; all are fixed, and the reviewer's probe cases became regression tests (`tests/audio-front-end.test.ts`).

| ID | Issue | Fix |
|---|---|---|
| M1 | `releaseLease()` stopped every lease: a stale session's late release killed the newer call's clone | `releaseLease(stream)` returns only that clone; `RealtimeDeps.releaseMicrophone(stream)` passes the route's own stream; the page's safeguard (`releaseAllLeases`) runs only when no call is active or starting. A concurrent-lease test was added |
| M2 | Page scripts could `POST {wake_listen:true}` and skip the native explanation | Turning on is possible only from the App main process through the same-process `NousHandle.wake.setListen` (reusing the pattern where the main process calls the core directly, as for identity and memory); HTTP answers 403 to `wake_listen: true`, and the page can only record `device_id` or turn listening off. The camera's `POST /api/settings/camera` has the same class of issue; it is tracked as a separate known item and not changed in this batch |
| m1 | Unplugging during a call with the preference off showed a wake error | The source is cleared on `ended`; `device_ended` is reported only when the preference is on and no call or pause blocks it (an unplug during a call is reported after the call, without reopening the microphone) |
| m2 | With the engine missing, the error caption repeated after every call | Each reason is captioned once until listening actually starts or the switch is turned off |
| m3 | The worker could be terminated before zero-filling | After clearing and releasing the detector the worker posts `closed`, and the main thread waits for it (at most 100 ms) before terminating |
| m4 | The static privacy tests could be bypassed | Every `postMessage` is checked against a fixed allowlist; `self.` (except the fixed form in the worker entry), `globalThis[`, `Reflect.`, `eval(`, `new Function`, `importScripts`, and `window[` are forbidden; `new URL(` may point only at the wake worker |
| m5 | Switching straight from voice mode to realtime voice could leave two `getUserMedia` calls pending | The reclaim after Web Speech ends is deferred to the next macrotask, and a lease in the same tick cancels it |
| m6 | The CSP was relaxed with the flag on even without an engine | `'wasm-unsafe-eval'` is added only when the engine check passes; the flag-off snapshots are unchanged |
| m7 | The worklet had no explicit mono downmix | `channelCountMode: "explicit"`, `channelInterpretation: "speakers"` |
| m8 | The start of ADR-0003 still said `AudioFrontEnd` and the worker do not exist | Updated in both languages |
| m9 | Turning the flag off in the core during a call stopped the call's clone | Always-on listening ends only after the call |
| Nits | Comments pointing to missing test files; the guard was not reset on disable; the menu said “Starting” before the page reported; turning it on from the menu while loading showed “resumed”; device end and engine load failure were captioned as “not on” | Comments point to the real files; `WakeGuard.reset()` on disable; “Not reported yet” before a report; the first-seen settings are applied before the latest; these two reasons now read “Always-on wake listening stopped: …” |

The wait in `capture.ts` and `channelCountMode` are covered only by static and type checks and have not run in a browser (Mac gate).
