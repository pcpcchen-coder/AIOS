# 中英文文件與 App／網頁驗證

日期：2026-10-26，Asia/Taipei。本批次由使用者要求：repo 說明文件提供英文，後續所有 Agent 維持中英文，並實作 App 與網頁雙語。既有尚未提交的家庭記憶工作保留；此紀錄不替記憶、相機、家電或真實語音宣稱驗收。

## 文件覆蓋與後續規則

既有 58 份專案 Markdown 說明皆有完整中英文。中文原稿保留路徑，新增 `.en.md`；原本英文的 Agent／技能／證據文件補 `.zh-TW.md`。本批新增的語言使用指南與本紀錄也成對提供，另有一份完整雙語規範。原始程式範例、指令及證據圍欄保持逐字一致，正文、表格、限制與歷史狀態完整翻譯；英文文件的本機 Markdown 連結與章節錨點已檢查。

`AGENTS.md`、`CLAUDE.md` 與 `.cursor/rules/bilingual.mdc` 均載明使用者要求。[雙語規範](../BILINGUAL.md)、`scripts/check-bilingual-docs.mjs`、對應失敗情境測試及 GitHub Actions 檢查已加入。檢查可找出缺版、失效的語言連結、圍欄差異及未審閱的內容變動；指紋不能代替人工翻譯審閱。

第三方 `vendor/pstack` 與註冊符號連結保留原樣，固定版本校驗通過：172 個上游雜湊、兩個客戶端各 56 項技能。原始日誌、JSON 證據、依賴清單與 HTML 設計樣稿不翻改；相關專案解說提供雙語。

## 程式與畫面結果

- 完整 `node scripts/verify-aios.mjs` 通過：69 個測試檔、1,086 項通過、1 項原有跳過，型別檢查、前端建置與隔離 mock HTTP 任務／成果／直接對話流程通過。
- 文件檢查工具的 5 項失敗情境測試通過，包含缺版、只改來源、程式範例差異、失去語言連結、孤立翻譯及不完整 inline 規範。
- `scripts/verify-bilingual-ui.mjs` 在真實建置頁面與隔離本機 mock 核心完成 5 項流程：繁中／英文設定及無障礙文字、重新載入保存、切換不取消任務且保留原文、往返切換與英文指令、英文唯讀指令頁安全標頭。英文設定與進度文字另檢查未遺漏的中文文案，保留刻意雙語的語言入口與使用者原文。
- `scripts/verify-bilingual-desktop.mjs` 使用真正 Electron 開發包及暫存 `userData`／設定，完成 3 項流程：原生選單同步前端且不重新載入、前端選擇保存到原生偏好、重新載入保留語言。沒有使用或修改正式 App 的資料。
- 既有 `scripts/verify-regions-browser.mjs` 的 9 項回歸流程通過。修改前的首次執行有 2 項因輸入框未聚焦而逾時；工具改成先點空白畫布再按 Enter，沒有刪除或弱化原斷言。
- 新的英文及繁中 macOS 權限說明已通過 `plutil`；桌面開發內容建置成功。沒有實際觸發系統權限提示來驗證其語言。

## 審查後修正

獨立審查與完整測試找出的問題均已修正並保留回歸測試：一般對話延遲交辦的語言、瀏覽器語音重啟及 TTS 的語言、家人登記未送出姓名與未成年勾選保留、逐字稿與姓名的二次翻譯、較晚回來的原生設定回應。只允許不含姓名參數的通用問候 helper 進 renderer；原本「名稱短句只由核心組成」的隱私檢查仍通過。

語言 IPC 僅接受主視窗、主框架與精確本機核心來源；測試明確列出新增的唯讀語言欄位與變更訂閱，家人管理請求仍只走原本的身分 IPC。英文確認必須明確包含動作，`yes`／`okay` 不是授權，否定優先，設備未確認時不翻成成功。
