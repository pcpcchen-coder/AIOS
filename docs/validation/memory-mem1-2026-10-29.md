## 2. 與 16 及核定方案的差異（照實記錄）

1. **簡體指令詞不觸發寫入。** 簡繁對照只用於搜尋 token；「记住…」當一般聊天，不為了湊指令而改寫使用者原文。
2. **更正與忘記只認句首動詞，而且要有明確的記憶目標。** 更正要「更正，…」或「更正／改一下記憶：…」；忘記要「忘記…」「忘掉…」或 `forget about/that …`。「把報告改一下」「這段文字幫我改一下」「我現在可以吃香菜了，改一下」「忘記密碼了怎麼辦」「forget it」都是一般聊天。找不到對應的記憶時，原句照樣交給模型（不回「找不到」）。16 §1 的「…，改一下」句尾說法因此不支援，要改用「更正一下，…」。
3. **一句話出現卡片時，問題暫緩。** 卡片處理完才送 chat，送出時用卡片回答取得的新 `memory_turn`。16 沒有規定這個順序；這是為了不讓未確認的人物或未保存的內容影響回答。
4. **「我是 X」只在 X 是既有人物時選人。** X 不是既有人物、句子也沒有接著「記住」時（「我是老闆」「I'm Fine」）就是一般聊天；接著「記住」才出「建立 X 的記憶檔？」卡。「現在是…」「這裡是…」「It's…」「This is…」不算自稱。同名選擇卡只在舊資料已有同名時出現。
5. **「已搬出」沒有資料欄位。** 家人辨識目前只有 `minor`，所以刪除家人時「同時刪除記憶」只有未成年預設勾選；已搬出的預設要等 identity 有對應欄位。
6. **同意以「服務＋帳號」分人物或全家共用保存。** 首次設定時，選定的人物與全家共用一起允許；之後在記憶管理只改選定的範圍。模擬模式沒有帳號，不送記憶。
7. **`reviewAfter` 一律為 null。** 欄位已保存，複查提問流程未實作。
8. **記憶管理的修改、忘記沿用 MEM-0 字面句型取得票證**（`更正：id@rev：內容`、`忘記：id@rev`）；釘選、刪除人物檔與連結家人辨識不是記憶內容寫入，改由原生確認（刪除、連結）與管理權杖把關，沒有票證。
9. **未成年人物：聊天與卡片都不能寫入、更正或忘記**，也不提供「改記全家共用」，一律回「請由家長在『記憶…』管理」；「你記得我什麼？」卡上的按鈕也不行。記憶管理可以新增、修改、忘記，也可以手動「標為未成年」（沒有連結家人辨識時也能標）。17 §9.5 的「待家長確認卡」增補提案沒有採用。
10. **重啟後的同句重送** 依「同一人物、同一標準鍵、同一內容」去重回 `unchanged`；store 的操作回條仍可查 `saved`／`receipt_expired`。
11. **撤銷時文字串流不送 `done`**；`memory_revoked` 是結束事件，頁面把這一輪標成停止並清掉含記憶的歷史。
12. **對話歷史清空範圍**：只要有一輪用過記憶，更正、忘記、換人、暫停（OS 鎖定、閒置、多人或追蹤中斷、刪除家人）或撤銷時整段清空；分不開哪幾句受影響（16 §8）。核心每個回應都帶本次人物世代（`presence.epoch`），世代改變時主程序也推一個不含內容的通知，頁面因此在沒有串流時也會清空。
13. **核心的記憶回條與純記憶指令不放進模型歷史。** 回條含記憶內容，放進歷史會讓之後換成沒有同意的服務帳號時經由歷史收到記憶；換服務或帳號時頁面本來就會清空對話。
14. **帶記憶後的交辦封鎖跨回合。** 這一輪或對話歷史有用過記憶，交辦一律改成「要交辦這件事嗎？」（標題用使用者原句）；語音來源走同一個對話，也一樣。核心另外記錄「上一次沒有歷史的請求之後是否用過記憶」，沒有 `memory_turn` 的請求也擋。
15. **敏感資料不收。** 密碼、權杖、卡號、帳號、病歷、診斷、身分證、護照等固定詞，以及連續長數字（≥6 位，或含空白與連字號的 ≥9 位），一律回「這類資料不能存進記憶」，記憶管理的新增與修改也一樣。
16. **「全部忘記」只在記憶管理。** 聊天說「全部忘記」只回提示，不刪；記憶管理的「忘記…全部記憶」要管理權杖，之後還有原生確認。
17. **開關記憶、改同意與選人都要憑證。** setup 只接受首次設定卡或記憶管理權杖；select 只接受主視窗「本次人物」選單的一次性 `select_card`（每個世代換一張）或管理權杖。
18. **Keychain 與建資料夾的時機。** status 不開記憶檔；記憶未開啟或不知道時，打字只跑 parser。只有說「記住…」、打開「記憶…」，或上次執行時記憶是開著的（`configDir/memory-enabled.json` 只存 `{ enabled }`，不含內容）時第一次打字，才開記憶檔。解不開金鑰後這次執行停用，只有從「記憶…」明確重試才再開。刪除家人時不為了算筆數去開記憶檔（對話框寫「刪除時一併處理」）。
19. **「記住今天」到期後在下一次寫入時清除並留墓碑。** 容量（1,000 筆）只算有效記憶，與 store 上限同一口徑；超量回 `full`。
20. **互動結束的定義。** 有鏡頭時：在場判斷結束（PresenceTracker 約 60 秒）或鏡頭停止＝追蹤中斷，取樣看到多張臉＝多人；轉頭或看鍵盤不算。無鏡頭時：閒置 30 分鐘。另加 OS 鎖定與刪除連結的家人。
21. **刪除家人與清除全部。** 單筆刪除照 George 決定 ⑨（成人預設不勾、未成年預設勾）。清除全部時原生對話框只能有一個勾選框，所以列出每位家人的筆數，未成年一律一併刪除，成人只有勾「同時刪除成人家人的記憶」才刪，否則只解除連結並暫停本次人物。記憶處理失敗時家人辨識畫面照實告知。
22. **信任邊界照實說。** SourceTicket 是核心的自我核對（防止核心把命令弄錯或被改動）；真正的安全邊界是 IPC 發送者檢查（主視窗主框架、本機核心頁面）加上頁面只轉送使用者打的字。自稱「我是 X」即可檢視與修改 X 在家中可用的資料：這是家中共用裝置上的人物分類，不是身分驗證。

## 3. 雲端（Linux）驗了什麼

### 30 組中文查詢

## 4. Mac gate（全部未執行，不能宣稱通過）

以下要在目標 Mac、正式簽章的 Nous App、隔離的記憶資料夾上由使用者操作或在場確認，用虛構資料，不讀現有 gallery。

1. 正式簽章的 Keychain：首次使用記憶時的系統詢問、允許後的跨程序重啟讀回；實際按「拒絕」後記憶停用、不建明文、一般聊天照常。
2. 真 `/usr/bin/lockf` 雙核心：同一個 userData 開兩個核心，第二個回「另一個 Nous 核心正在使用記憶」。
3. SIGKILL：正式 App 寫入途中強制結束，重開後回條與資料一致。
4. 效能：1,000 筆有效記憶下，暖檢索 p95 ≤50 ms、持久寫入 p95 ≤300 ms；另記首次解鎖與完整使用者等待，不把 Keychain 提示時間藏在平均數裡。
5. 臉部候選與互動結束：看著說話認出已連結的家人後打字，出現「這次用 X 的偏好？」，確認才選定；多人入鏡、人離開鏡頭（在場判斷結束）或鏡頭停止時暫停；只是轉頭或看鍵盤時不暫停。
6. OS 鎖定：鎖定螢幕再解鎖，本次人物為暫停、進行中的回覆停止。
7. UI 截圖：首次設定、澄清卡、建立人物、清單（修改／忘記／釘選）、記憶管理、刪除家人的勾選對話框，中英文各一份。
8. 真 Claude 與真 ChatGPT 帳號的 M02：同一筆記憶在兩個服務各取一次；換帳號未同意時不送。
9. Time Machine 排除結果與 `nous.log` 的 canary 掃描。
10. `safeStorage.isEncryptionAvailable()`（settings 回報 available 時會呼叫）會不會觸發 Keychain 詢問；記憶沒開時啟動、查狀態與一般聊天都不應出現 Keychain 詢問或建立 `userData/memory`。
