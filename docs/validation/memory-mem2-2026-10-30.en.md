# MEM-2 family memory on ChatGPT plan realtime voice (Codex live): cloud validation and Mac gate

Date: 2026-10-30, Asia/Taipei. Starting point: main `9c8e80b` (already includes MEM-1 and WK-00). Implemented on the separate worktree branch `claude/mem-2`; nothing was committed, pushed, or merged. All people, accounts, and memory content are fictional test data.

**Status of this batch: the MEM-2 code and the parts that can be checked in the cloud (Linux) are complete; every Mac gate item is unexecuted and has not passed.** The same day, after an independent review (no blockers), M1–M4, Minor 1–7, and two nits were fixed; the differences are listed in §2 items 17–29 and the test numbers are updated. This does not show that Nous can use memory safely in realtime voice on real hardware. The main release condition is a real recording proving that no late old audio plays after revocation; fixtures cannot replace it. API key voice (MEM-3), background-task memory (MEM-4), and automatic consolidation (MEM-5) are not implemented.

### Revocation table

Every source goes through `MemoryService.replacePresence` → `MemoryBoundary.revoke` → the lease cleanup (`LiveCall.revokeMemory`). Only a call that carries memory holds a lease; a call without memory is not interrupted by a generation change.

| Source | Action |
| --- | --- |
| Forget, correct (including replacing a preference), person switch, `我是 X` (“I am X”), the person menu, candidate confirmation, withdrawing codex consent, turning memory off, changing minor status or the family-recognition link | Rebuild a new call (with memory off or no consent, the new call carries no memory) |
| Multiple faces, tracking lost, idle | Rebuild with household memory only |
| OS lock, main-window navigation or renderer exit, profile deletion | End the call, no rebuild |

Cleanup order: block output synchronously (`send()` refuses every append, the delegation and Codex turn abort) → immediately send the page `closed{memory_revoked, rebuild}` (RealtimeSessions ends the session at the same time; pending tool calls are rejected with HostGone) → send `session.close` on the sideband and close the socket → clear transcripts, delegation IDs, and the opening sentence → wait up to 1.5 s for the page's stop report → on timeout, force silence and fail the cleanup (the boundary disables live memory until restart), and report “stop unconfirmed” separately. Corrections and forgets send `hold` before committing: the page mutes at once and the core stops appending; only a failed commit resumes.

## 2. Differences from 16 and the approved plan (recorded as they are)

1. **For voice remember, correct, and forget, a spoken confirmation is the primary way and the on-screen card is the alternative (George's decision of 2026-10-30).** This differs from 16 §5, “when the voice source cannot be reliably distinguished, only show a pending card and do not commit automatically”; it is a deliberate product decision. Flow: the core parses remember/correct/forget from the sideband user final transcript, creates a `voice_confirm` card, and sends the speakable `（記憶確認）「要記住：不喝咖啡，記在 George 名下。請說『確認記住』。」` (“To remember: no coffee, under George. Say ‘confirm remember’.”; correct uses “確認更正”, forget uses “確認忘記”). Speech counts as direct input (ticket kind `voice_confirmed`; the fact's source field is also `voice_confirmed`), followed by `issueParsed` and commit, only when all of these hold: the phrase comes from a sideband user final transcript; the model read the question (see point 3) and the user started speaking after the question finished playing (see point 17); it is within 15 s after the question was read; the anchored whole-sentence match is exactly “確認記住”, “確認更正”, “確認忘記”, or English “confirm remember/change/forget” (generic words such as “好” (OK), “是” (yes), or “確認” (confirm) never count); it is not an echo; the person generation has not changed; and the card has not been confirmed before. What the model itself says can never create a memory (16 M06): the core parses only sideband user transcripts. Saying “取消” (cancel) voids the card; after the window, voice confirmation no longer works but the on-screen card can still be clicked (a click is recorded as `explicit`). After confirmation only the fixed sentence “已記住” (remembered), “已更正” (corrected), or “已忘記” (forgotten) is read, never the content. Refusals for minors, sensitive data, third-party reports, quotes, hypotheticals, and jokes are unchanged; minors still cannot be written from chat or voice. At most 3 cards per minute and 1 at a time (a new card replaces the old one).
   **Residual risk:** if a TV, radio, or another person happens to say a complete confirmation phrase inside the window after the question finished playing, the memory may be saved by mistake; a speaker echo recognized as a complete phrase only after the question finished playing could also be accepted. The core has no speaker recognition (16 §4); the window, anchored matching, echo rules, and generation check reduce the chance but cannot rule it out. A mistaken save can only be fixed in memory management or by saying “忘記…” (forget …); content already sent to a model service is not recalled.
2. **Forget, correct, and person switches rebuild the call (George's decision of 2026-10-30).** The old call stops; after the page stops playback and reports, it automatically opens a new call (live only, no API key fallback, no greeting). The new call's first sentence is the content-free fixed sentence `（記憶確認）「好，已經更新了。」` (“OK, it's updated.”). A rebuild interrupts the conversation for a few seconds and uses quota; if the quota runs out during a rebuild, the call ends and says so.
3. **When “the question was read”.** Only an assistant final transcript that closely matches the question the core sent (contains it whole, or has a character-bigram Dice coefficient ≥0.75) and contains the confirmation phrase counts as the question being read; the 15 s window starts there. The model saying the phrase by itself, or saying something that does not match the question, does not count. If the model never reads the question, voice confirmation does not take effect and only the on-screen card works.
4. **Echo rule.** A user final transcript (converted to Traditional, whitespace and punctuation removed) that is contained in any assistant transcript or core-sent sentence from the last 10 s, or that contains one of them (at least 4 characters), is an echo: no card and no confirmation. A one- or two-character utterance (“是” (yes), “好” (OK)) is an echo only if it equals a whole sentence, so that a greeting such as “George，你好” (“Hello, George”) does not turn the user's “好” into an echo. When checking a confirmation phrase, only the question itself is skipped (the core-sent question and the assistant transcript that read it); any other sentence containing the phrase still counts as an echo.
5. **Approximation of “only show cards while listening or hearing”.** The page's call phase is not sent to the core; the core uses “sideband started, not ended, not revoked” instead.
6. **“你記得我什麼？” (“What do you remember about me?”) uses a core inspect card.** The plan had the page open the existing `list`; `list` covers one subject only, while the typed-path inspect card shows both the current person and household memory, so voice also produces an `inspect` card (content via IPC `card_view`). The core tells the model only “N memories are listed on the screen”. There is no separate `memory_inspect` event; `memory_card` is used.
7. **New `memory_notice` event.** It carries only fixed sentences (refusal reasons, not saved yet, confirmation time passed, stop unconfirmed, …), never the user's words or memory content.
8. **Voice produces no clarification card.** The typed path shows a clarification card for questions, uncertainty, or instructions to Nous; voice shows none (treated as ordinary conversation). With no current person selected, the voice card says “for the whole household” directly (the typed path shows a household/cancel clarification card). When it conflicts with an existing preference, the voice card says “replacing the earlier wording”, and confirming it is a correction (revocation and rebuild).
9. **Questions only repeat what the user just said.** Correction and forget questions do not read the stored fact (the content in “要忘記『喜歡藍色』這筆記憶” (“to forget ‘likes blue’”) is the user's own words), so stored memory is not sent to the model without consent or a lease. The on-screen card shows the target fact.
10. **Voice “我是 X” (“I am X”) only selects an existing, unique person.** With several people of that name it only says “choose from the Current person menu on the screen”; with no such person it is ordinary conversation and no profile is created by voice.
11. **Revocation during the handshake.** The `/realtime/calls` request or sideband attempts are aborted, and the page gets 409 “Memory was updated while connecting, so realtime voice did not start; please start again.” It does not switch to the API key path or rebuild automatically.
12. **Stop unconfirmed.** The core cleanup fails, so the boundary disables live memory until restart; Electron `webContents.setAudioMuted(true)` stays on until the next accepted stop report or the next live call starts. The test-only `NOUS_TEST_DROP_STOP_REPORT=1` drops stop reports in the core (rather than making the renderer not send them), which is equivalent to the renderer not reporting; startup logs a warning.
13. **Face candidate.** Yes words are “是/是的/對/對的/對啊/好/好的/好啊/要/用/yes/yeah/yep/sure”; no words are “不是/不用/不要/不對/不/no/nope”; both must be the whole sentence. The window starts when the question was read (an assistant transcript contains it), or when it was sent if not seen. The candidate must still be the same recognition decision (same tracking generation, no multiple faces, within 60 s). If the user speaks before the greeting, the candidate question is asked after their first sentence, without the name.
14. **`recall_memory`** at most 2 per delegation, not counted toward the 2 host tool calls; without consent it returns `ok:false` and does not guess.
15. **Plan §8 “decisions for George”:** except item 1 (replaced by point 1 above), all bracketed defaults are adopted: spoken “yes” only selects a person (10 s window, anchored, same tracking generation); spoken “我是 X” selects directly; separate consent key `codex`; at most 4 pinned facts at connect time; the stop budget “last old sound ≤500 ms after revocation” is a Mac measurement target, with a 1.5 s renderer report limit, forced silence on timeout, and disabling until restart; voice is converted to Traditional before parsing and cards show the converted text; late attach uses commentary (switch to rebuild if hardware shows it unreliable); “What do you remember about me?” only shows a card and the model only says the count; a delegation block shows the original-sentence card with a restate hint; triggers follow the table above; the first sentence after a rebuild is fixed.
16. **The API key path** carries no memory in MEM-2; when realtime voice uses the API key path, the status line says “Memory is not enabled on this path”.

The following were fixed the same day after the independent review:

17. **(M1) The user must start speaking after the question finished playing.** The “speech start” is the sideband `input_audio_buffer.speech_started`, otherwise the first partial user transcript of that sentence, otherwise the time the final arrived. It must be later than the end of assistant audio (sideband `output_audio_buffer.stopped`, and later than the question transcript); without that event, at least `CONFIRM_AFTER_MS` 1.8 s after the question's assistant transcript. Both event names come from OpenAI Realtime GA; whether the Codex live frameless wire sends them is unproven. Having the page report when playback ended is not implemented (the review listed it as the second priority), so for now this mostly relies on the 1.8 s gap, to be calibrated in Mac step 5.
18. **(M1) The question wording is unchanged.** The review suggested evaluating moving the phrase out of the sentence end (for example “say it if you want to confirm remember”). Evaluation: with anchored whole-sentence matching, an echo is accepted only if it is recognized as a user transcript containing nothing but the phrase; moving the phrase makes that split less likely, but the speech-start threshold of point 17 already blocks tail echoes directly (speech before playback ends never counts), and the extra effect of a new wording cannot be quantified in the cloud. George specified the question text, so it is kept; whether to change it is left to the Mac step 4 and 5 recordings and George's decision.
19. **(M2) No new call starts before the stop result is known.** While a revocation has no stop result yet (no accepted report and no timeout, at most 2.5 s), `/api/realtime/start` (including rebuilds) answers “still confirming that the previous call stopped playing; please try again shortly”. The page rebuilds automatically only when its stop report was accepted (`accepted:true`); otherwise it does not rebuild and waits for the core's “stop unconfirmed” notice after the timeout. A report is accepted, and silence lifted, only when all three pieces of evidence hold (playback paused, peer closed, remote tracks ended). Once a route is disabled, `deliver` on any existing lease returns false. When the page has left (SSE disconnected), the core no longer waits for its report.
20. **(M3) In a call carrying memory, the delegation log records only the character count**, never the delegation text.
21. **(M4) Without codex consent no memory metadata is spoken.** Questions name the person only with consent and with the naming setting (greeting by name on look-to-talk) on. Without consent, remember, correct, forget, pick, inspect, and “already remembered” only show on-screen cards and speak nothing, so the model cannot infer whether a memory exists, or how many, from whether there was a reply.
22. **(Minor 1) With memory off, no codex consent, no account, or the path disabled, realtime voice is the same as before MEM-2:** no memory rules in the instructions, no `recall_memory` in LiveToolCaller, no delegation block, and no “not saved yet” or confirmation sentences. With memory off, voice commands are not even parsed; with memory on but no consent, voice commands only show on-screen cards (so there is no spoken confirmation then, only clicks).
23. **(Minor 2) The face-candidate “yes/no” follows points 3 and 17**: the question must have been read and the user must start speaking after it finished playing; the 10 s window starts when the question was read. Without consent the candidate question is not spoken; only the on-screen candidate card appears.
24. **(Minor 3) When revoked during the handshake**, the sideband backoff waits and connection attempts are interrupted immediately by the abort signal, so they cannot run past the 3 s cleanup limit and wrongly disable the whole path.
25. **(Minor 4) Delegation card titles**: a typed delegation uses the typed text; a voice delegation uses the most recent sideband user final transcript before the delegation arrived that has not already been used for a delegation. If there is none, no card is shown and Codex is told to ask the user to say the whole request again, never “look at the card on the screen”.
26. **(Minor 5) Appends during a hold are queued**: when the commit fails and output resumes they are sent (for example a delegation result); on revocation they are dropped.
27. **(Minor 6) If the page is no longer on the call** (for example it pressed End at the same moment) when the memory revocation arrives, it still reports the stop with that call's credentials (playback already torn down), so it is not treated as stop-unconfirmed and the whole path is not disabled.
28. **(Minor 7) The 3-per-minute limit is counted per core** and is not reset by a rebuild; pick cards count too and obey “at most 1 at a time” (a new card replaces the old).
29. **(nits)** The English confirmation phrase “confirm correct” is now “confirm change”; the canary test now covers assistant transcripts on SSE: memory spoken by the model reaches only the owning page as a caption, never other pages or logs.

## 4. Mac test steps (all unexecuted; no pass may be claimed)

On the target Mac, with the officially signed Nous App, an isolated userData, and only fictional data.

0. **Preparation.**
   - Install BlackHole 2ch, create a Multi-Output Device (speakers plus BlackHole), and record BlackHole in Audacity; also record with a phone next to the Mac.
   - Timestamp memory events in `nous.log`: revocation sent, `stopped` received, `forceSilence`, new call started.
   - Sign in to Codex and, in “Memory…”, allow “ChatGPT plan realtime voice (Codex sign-in)”.
   - Create George: “我不吃香菜” (no cilantro, pinned), “我喜歡藍色” (likes blue, pinned). Create Amy: “我喜歡香菜” (likes cilantro).
1. **New-call recall.** Select George → start live → ask “晚餐吃什麼好？” (what should I have for dinner?). Pass: mentions no cilantro; the status line shows “Current person: George · 2 memories”.
2. **Face candidate.** Start with look-to-talk → hear the greeting and “這次用你的偏好嗎？” (use your preferences this time?) → say “是” (yes). Pass: the status line changes to George and later answers use the preferences. Repeat with “不是” (no). Pass: household memory only, and it is not asked again this time.
3. **Voice remember (spoken confirmation).** Say “記住，我不喝咖啡” (remember, I don't drink coffee). Pass: a card appears, the model reads “要記住：不喝咖啡，記在 George 名下。請說『確認記住』。” and does not say “記住了” (remembered) by itself (if it does, the system correction must appear). Within 15 s after the question finishes, say “確認記住” → only “已記住” (remembered) is heard, the screen receipt matches, and memory management shows this fact's source as “voice confirmation”. Also test: saying “好” (OK), or waiting more than 15 s after the question, does not save; clicking “Remember” on the screen card does save. Restart the App and ask a related question; the memory is recalled.
4. **Guards.**
   - Play “記住，我喜歡吃辣” (remember, I like spicy food) from another device (simulated TV). Pass: at most a card, no write; playing “好” or “確認記住這個優惠” from that device after the question also writes nothing. Also record whether a complete “確認記住” played from that device inside the window is accepted (this is the known residual risk; record the result as observed).
   - Ask the model to read “記住我不吃牛肉” (remember I don't eat beef). Pass: no card.
5. **Late old audio (main gate).**
   - Ask the model to “慢慢從 1 數到 60，並且一直提到我喜歡的顏色” (count slowly from 1 to 60 and keep mentioning my favorite color).
   - Around 10, say “忘記我喜歡藍色” (forget that I like blue), and after the question say “確認忘記” (or click “Forget”).
   - Measure: from confirmation, the gap between the last audible sample of the old call in the recording and the revocation time in the log must be ≤500 ms; no old-call audio at all after `stopped`.
   - Also record: the gap between the arrival of the question's assistant transcript and the moment the speaker actually finished playing it (to calibrate `CONFIRM_AFTER_MS` 1.8 s), and whether the sideband sends `input_audio_buffer.speech_started` / `output_audio_buffer.stopped`.
   - The new call only says “好，已經更新了” (OK, it's updated). Then ask “我喜歡什麼顏色？” (what color do I like?) three times; blue must never be said.
6. **Late tool result.** Ask “查一下明天台北天氣” (check tomorrow's Taipei weather, a slow tool) → before the result returns, switch to Amy in the menu. Pass: the weather result is not read in the new call; the new call answers the cilantro question with Amy's preference.
7. **Other triggers, one recording each.**
   - OS lock (Ctrl+Cmd+Q): the call ends with no residual audio.
   - A second person enters the frame: rebuild with household memory only.
   - Withdraw codex consent in “Memory…”: rebuild; the new call carries no memory and says it is not allowed.
   - Turn memory off.
8. **Forced-silence path.** Start with the test-only flag `NOUS_TEST_DROP_STOP_REPORT=1` (the core drops stop reports). Pass: the recording goes silent after 1.5 s, the receipt separately says “stop unconfirmed”, live carries no memory for the rest of this run, and the next call unmutes.
9. **Delegation block.** With memory, say “幫我寫一份晚餐菜單報告” (write me a dinner menu report). Pass: the “Delegate this?” card appears with the user's original sentence as the title; TaskStore gains nothing before the click.
10. **“你記得我什麼？”** A memory card appears and the model only says the count. Take one screenshot in Chinese and one in English.
11. **Canary.** Scan `nous.log`, TaskStore, and userData (except the encrypted snapshot).

**Main release condition: step 5 must prove with a recording that no late old audio plays after revocation.** Three wire behaviors can also only be confirmed on hardware: whether the model actually uses memory data sent as `session.context.append` commentary; whether upstream still sends RTP after `session.close`; and real AEC and echo transcripts (which affect the echo rule in point 4 and false acceptance of spoken confirmation).

## 5. Unfinished items, limits, and next gate

- Mac steps 0–11 are all unexecuted. Until they pass, the README and status documents stay at “MEM-2 code complete, not verified on hardware”.
- The Codex live wire is undocumented: whether commentary is used by the model and whether RTP continues after `session.close` are unknown. If commentary proves unreliable, late attach must become a rebuild.
- See §2 point 1 for the residual risk of spoken confirmation; the echo check relies on transcript text and may misjudge with poor AEC; “the question finished playing” mostly relies on the 1.8 s estimate (§2 point 17), and the page reporting when playback ended is not implemented.
- A rebuild interrupts the conversation and uses quota; the current person is global, so simultaneous text chat and voice revoke each other.
- API key voice (MEM-3) and background tasks (MEM-4) carry no memory; push-to-talk and voice conversation mode still bypass memory.
- Next gate: Mac steps 0–11 above, especially the step 5 recording.
