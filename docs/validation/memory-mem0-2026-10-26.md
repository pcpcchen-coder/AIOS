## 批次計畫與工作分界

依 pstack Feature 的理解、設計、實作、審查、驗證與交付順序工作。記錄器 run 為 `run-20261026094802-af38b4`，留在 `.pstack/observability/runs/`。使用者本次未授權發布，sidecar 使用 local-only 模式。第一次從原型目錄呼叫 recorder 因路徑錯誤失敗，已改回 repo 根目錄記錄，未把失敗當成成功。

- Blocking first steps。先核對 origin/main、本機修改、CLAUDE、現況、16 與 ADR-0002，再探查既有儲存及語音關閉程式。
- Independent workstreams。儲存、桌面探針與來源／生命週期分別擁有不同檔案；獨立審查只讀，不互相覆寫。
- Shared mutable state。產品準據是一份加密快照，必須由同一持鎖核心序列化提交。測試及探針各用獨立暫存目錄。
- Smallest safe decomposition。只做 MEM-0，沒有先接 UI、HTTP、模型或背景任務。每個模組先有隔離證據，再檢查整體回歸。

套用 Model the Domain，把來源 capability、session 世代與通話 lease 放入私有 registry。套用 Sequence Work into Verifiable Units，這批先交付隔離基礎，再由 MEM-1 接產品文字閉環；未過語音 gate 的路徑維持停用。同模型的獨立設計與審查不構成跨模型多樣性。

`MemoryStore` 沒有 HTTP、模型與人物授權概念，不能直接暴露給 renderer。MEM-1 的 MemoryService 必須先驗證來源，再呼叫它。`read()` 也只供核心，不能把完整快照或去重金鑰交給模型。

快照使用每次更新的新 DEK 與 nonce、AES-256-GCM，以及綁格式／版本／包裝金鑰的 AAD。只有密文會進暫存檔。保存順序為檔案 fsync、rename、目錄 fsync，最後才更新記憶體並回成功。資料與不含正文的回條位於同一密文。無法解鎖、損壞、權限不符或寫入失敗都不退回明文，也不覆寫成空庫。

單寫入者使用 macOS `/usr/bin/lockf` 對 Node 繼承的 fd 取得 BSD 鎖，由核心持續持有該 fd。鎖檔不刪除，不使用可能競爭的 PID stale-lock 清除。實測另一 Node process 被拒，持鎖核心遭 SIGKILL 後由 OS 釋鎖。這是目前 macOS 限定的實作，其他平台停用。檔案鎖不是防同一 OS 使用者惡意竄改的安全邊界。

回條最多 2,048 筆，指紋採快照私有金鑰的 HMAC，不保存原句或可直接字典比對的裸 hash。審查實測發現只用 caller 時間的 floor 會讓淘汰 ID 變造時間後重放，因此改成核心產生 UUIDv7 形狀 ID，48-bit 時間必須等於 `issuedAt`，保留 74-bit 隨機量。floor 可拒絕已淘汰的原 ID。相同毫秒已有大量操作被淘汰時，該毫秒未提交的其他操作也會保守拒絕，必須以新直接輸入建立新操作。MEM-1 須統一使用 `newStoreOperation`，不可讓模型指定 ID 或時間。

兩個來源方案比較後採 WeakMap opaque object，沒有 wire bearer token。JSON、clone、其他 service 或重啟均不能製造相同 capability。來源票證綁定核心觀察的輸入、session、人物世代、序號、期限及完整命令。MEM-0 僅接受精確的隔離語法 `記住：內容`、`更正：id@revision：內容` 與 `忘記：id@revision`，不代表已有自然語言理解。語音來源、可信主視窗輸入與確認卡仍須 MEM-1／MEM-2 接線及驗收；模型或文件的 `source: user` 不構成權限。

`withVoiceContext` 等到 adapter 的 `closed` promise 才釋放，握手完成不會結束 lease。撤銷先同步阻擋交付、安裝共享 barrier，再 abort，然後等待只執行一次的 cleanup。pending 握手也包含在 barrier；逾時只能回失敗，晚到建立的連線仍會清理。連線建立或通話失敗也必須清理；清理失敗或逾時停用該路徑，不能回完整撤銷成功。production `live` 及 `api_key` 在此模組一律拒絕。沒有更動任何既有語音路徑，也沒有向其注入記憶。
