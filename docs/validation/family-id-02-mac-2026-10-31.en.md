## Findings

- **F1: on the API key route the model rewrites or adds to the sentence.** In 2 of 9 tries it did not say the given sentence: once it prefixed "好的，我明白了，我會照您說的來：", once it replaced it with "好的，我明白了。那麼我們就接下來可以開始。". Under ID-02 §5 this fails the route. Not seen on the ChatGPT plan in this round.
- **F2: speech during "connecting" is lost.** The microphone opens only when voice is ready (about +5 s); anything said while "connecting" is not heard, so the greeting still plays. Typing is not affected.
- **F3: background noise is taken as speech.** Noise is transcribed as words such as "被談", "Hej, lovs." or "对。", which makes Nous think the user spoke first (no greeting) or cuts an answer short. Transcripts are often in Simplified Chinese (same as HIST-1 F1).
- **F4: a brief head turn reset recognition (fixed, PR #57 `162d842`).** Turning away for a moment during an interaction started a new tracking generation, dropped the evidence and led to `not_eligible`. Turning away for less than 0.8 s no longer resets it; calibration can adjust this. The core still names only from the latest fresh frame, so a different person cannot inherit the name.
- **F5: when standing, the face was out of frame (new calibration feature, PR #58 `7cc99f6`).** Per-frame logging showed seated positions (0.8–1.0 m) were mostly good while standing (1.3–1.7 m) was `no_face` on every frame. There was not a single `unknown` all round, so the issue is camera angle and distance range, not the match threshold. After adding "Calibrate face recognition", the applied values were: farthest 1.85 m, glance grace 1500 ms, turned-face tolerance 0.29; the next 4 looks all named George.
- **F6: palm stop never fired (fixed, PR #57 `29f4238`).** A hand raised high scored only 0.60–0.68 for an open palm (threshold 0.7); a palm in front of the face scored enough (0.70–0.72) but the wrist was about 30 px below the shoulder, so each pose missed one condition. The code also ignored the palm while "connecting". Fix: threshold 0.55, the wrist may sit up to about a quarter shoulder-width below the shoulder, and a palm while "connecting" ends the voice session.
- **F7: a palm during a lookup stops the speech, but the result is still read out later.** For example, after "我查一下" is stopped, the search result arrives and is answered anyway.
- **F8: the first recognition right after launch may not name.** Family data loads on first use; at 00:33 it was not yet loaded when the decision was made (`not_eligible`, 0 frames). After switching to fixed signing, the 02:39 restart loaded it within 3 s and named George on the first look; keep observing.
- **F10: on the ChatGPT plan route, speaking first does not cancel the greeting.** When the user spoke after voice ready but before the greeting decision (within about 0.6 s), the greeting still played; the API key route skips the greeting in the same situation.
- **F11: an open voice session picks up other people's conversation at home.** During step 9 the voice session took in nearby people talking (private matters, not recorded here); the model answered them and introduced itself as "ChatGPT" in Simplified Chinese. Once look-to-talk opens voice it listens until the session ends, so nearby conversation is sent to the cloud and answered. To evaluate: whether to end automatically when nobody is talking to the screen, and the model's self-introduction and Traditional Chinese output. After evaluating, George chose to strengthen only the instructions on both routes for now (branch `claude/f11-voice-persona`): call itself Nous, never ChatGPT; stay silent when the speech sounds like other people talking to each other; answer in Traditional Chinese even when the transcript is Simplified. Muting the microphone or ending early when nobody faces the screen was not adopted, so nearby speech is still sent to the cloud, but the model should not answer it; the next Mac round must check whether the model follows this.
- **F9: the test tooling caused one blank page.** With a DevTools breakpoint attached, the main window once became `about:blank`; restarting the App fixed it. Cause unknown; not seen in normal use.

### Why F2 does not buffer audio

Recording speech during "connecting" and forwarding it after connecting was considered and not adopted:

- A WebRTC microphone track cannot send past audio, and the ChatGPT plan route (frameless) has no event for appending audio.
- On the API key route `input_audio_buffer.append` could in theory forward it, but that means holding seconds of raw audio in page memory and sending it over the data channel, adding a place where raw audio is kept and making the two routes behave differently; ordering against the server VAD and echo handling cannot be verified offline.
- Local level detection compares a single number; nothing is stored, forwarded, written to disk, logged or traced, which keeps the red line that raw audio is never written, traced or sent out, and it behaves the same on both routes. The cost is that the user has to say it again, and the screen says so honestly.

The threshold (RMS 0.03 for 300 ms) is an estimate and is not calibrated; F3's household noise or a TV may also exceed it and cancel a greeting. If needed, adjust it with `NOUS_EARLY_SPEECH_RMS` and record the peak RMS in the log line when it fires.

### F7 switch and risks on the ChatGPT plan route

- Switch: `NOUS_PALM_QUIET_DELEGATION` (on only for `on`, `1` or `true`), **off by default**. When off, a palm stop on the ChatGPT plan route only mutes local playback until the turn ends; the delegation still ends with speakable and the search result may still be spoken later (F7 is not fixed on this route until the Mac check). The API key route is not affected by the switch: there the core and the page control `response.create`, so a result can be returned without asking the model to speak.
- Conflict with the 2026-10-23 conclusion: item 5 of the [ChatGPT plan realtime voice validation record](live-voice-2026-10-23.en.md) concluded that every delegation ends with a speakable `delegation.context.append`; OpenClaw's `runDelegation` sends speakable on both success and failure, and its source has no example of ending a delegation with commentary only. With the switch on, a delegation in the stopped turn ends with commentary only, which is an unverified use.
- Risks: upstream may treat that delegation as unfinished; the model may keep waiting and say something else after an upstream timeout; the next turn may hang. That is why the default keeps the conservative old behaviour.
- Turns use "≤": delegation results for the turn at the stop and every earlier turn are not spoken. The review found that the user saying "停" while raising a palm, the echo of "我查一下", or noise can advance the turn before the stop-reply arrives; with "=" the old result would be spoken and the new turn silenced instead. Every `speech_started` starts a new turn, and user speech after an assistant reply always starts a new turn, so a noise transcript without an end cannot freeze the turn count.
- MEM-4b protected delegation (API key core sideband): the delegation feedback of the stopped turn (for example the delegation card's explanation) is not spoken, but the delegation card stays on screen and the user can still handle it there.

### Known limitations

- Whether the ChatGPT plan data channel or sideband sends `input_audio_buffer.speech_started` is still unconfirmed (see the comment in `shared/frameless.ts`); without it, partial transcripts and local level detection apply.
- Whether the model stays silent on a `commentary` `delegation.context.append` can only be confirmed on the Mac.
- `output_modalities` and `tool_choice: "none"` on `response.create` are OpenAI Realtime GA parameters, but nothing was sent to OpenAI offline; if they are rejected, DevTools shows a `[realtime]` error and that session does not greet.
- Esc interruption is unchanged and still stops only the part being spoken; only the palm stop drops this turn's late tool results.
- By default F7 is not fixed on the ChatGPT plan route (mute only); the default can change only after `NOUS_PALM_QUIET_DELEGATION` is turned on and Mac step 5 passes.
- When the core skips the greeting, it takes and discards the opening sentence it had already picked, so nothing is left for later.
