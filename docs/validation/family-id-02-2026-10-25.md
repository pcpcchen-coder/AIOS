## 3. 設計重點

### 3.1 時序：辨識不延長面向等待

```
在場確認(500 ms) → 面向確認(300 ms) → 停留(設定秒數 − 0.3 s) → startTalk（原時間）→ 語音連線 → 就緒 → 600 ms → 問候決策 → 送出
                                   └─ 同步取樣（停留期間＋連線期間，≤4 Hz）────────────────────────────┘
```

`SenseController.tick()` 先照原規則決定要不要 `startTalk`，之後才回報快照；同步辨識不能延後或阻擋開始。模型冷啟動或沒有任何一格時，核心決策是 `no_evidence`，照常說「我在」。

### 3.2 問候前的 6 個條件（14 §3）由誰檢查

| 條件 | 頁面（`eligible`） | 核心 |
|---|---|---|
| 1 同一互動與世代 | 互動 ID 相同、綁定世代＝目前世代 | 最後一格的世代＝綁定世代 |
| 2 只有一位互動者 | 這個世代沒看到多張臉 | 世代內沒有多張臉、沒有兩位家人 |
| 3 仍在近距離面向、證據新鮮 | 仍在場＋近距離＋面向＋鏡頭 ok | ≥3 格、跨 ≥500 ms、最新 ≤1 秒、品質合格 |
| 4 person 仍存在、gallery 版本未變 | — | 仍在可比對名單；登記資料改變時證據與待取短句清掉 |
| 5 問候開關仍開、未送過 | `take()` 前後各讀一次「看著說話時先打招呼」 | 稱名設定仍開；每個互動 ID 一次 |
| 6 使用者未開口／打字／收起／關鏡頭／結束 | 開口、打字、收起、結束 → skipped（完全不問候）；關鏡頭 → 世代加一（不稱名） | 鏡頭關 → 不稱名 |

姓名條件不符：移除姓名、仍說「我在」。取消條件（先開口、打字、收起、結束）：完全不問候。

### 3.3 姓名出現在哪裡

見 ADR-0001 §2.4.1 的表。摘要：核心組句；**API key 路徑的組好 instructions 會短暫經過 renderer**（IPC 回應 → `response.create`），live 路徑頁面只碰互動 ID；兩條路徑的模型逐字稿都會以字幕顯示（使用者本來就會聽到）；新增的 log 沒有姓名、person_id 或分數。名字被念出之後也會跟著對話走：ChatGPT 方案路徑的交辦請求會附最近的逐字稿送到 Codex，模型也可能把名字寫進任務標題（存成本機 JSON、送到任務引擎），所以「雲端只收到短句」不成立，只能說問候本身只送一句短句。

## 5. 待 George 在 Mac 上實測

**準備**：同 [ID-01 驗證](./family-id-01-2026-10-25.md) §6（`npm run face:setup -- --product`、`cd desktop && npm start`，`.env` 設 `NOUS_CAMERA=on`）。先在「家人辨識…」登記 George（至少再一位家人更好）。設定確認「看著說話」「看著說話時先打招呼」「打招呼時稱呼認出的家人」都開。打開 DevTools console 看 `[看著說話時序]`；`tail -f ~/Library/Application\ Support/Nous/nous.log | grep 問候決策` 看核心決策原因。記錄 Mac 型號、晶片、macOS、Electron 版本。每一項兩條路徑各做一次（設定「即時語音路徑」選 API key，再選 ChatGPT 方案）。

1. **George，我在**：George 從 2 m 外走到 1.0 m，正面看螢幕，不說話。預期：看著說話照原秒數開始，「聆聽中」約 0.6 秒後聽到「George，我在」，只說一次。記錄**實際聽到的整句**、字幕的逐字稿與 log 的決策原因（應為 `ok`）。**模型若加話（例如「George，我在，有什麼需要幫忙？」）、改字、猜別的名字或重複，該路徑記為不通過**，不要只看 log。
2. **陌生人或沒登記的人**：同上。預期只聽到「我在」，log 原因 `unknown`（或 `collecting`／`no_evidence`）。
3. **先開口取消**：看著說話一開始（「連線中」或剛「聆聽中」0.6 秒內）就說「新竹天氣如何」。預期：沒有問候，直接回答；log 沒有這次的「問候決策」（開口後頁面不再向核心要決策）。另做一次在連線中打字。
4. **換人**：George 面向到看著說話開始後立刻轉身離開，另一人在 1 秒內走近面向。預期：不叫 George；只說「我在」或不問候。
5. **多人**：George 與另一人同時在 1 m 內面向。預期：不稱名（log `multi_face`），可以說「我在」。
6. **稱名關閉**：在選單列「鏡頭與語音設定」取消「打招呼時稱呼認出的家人」。預期：只說「我在」，log 原因 `naming_off`；`Activity Monitor` 中看著說話時沒有額外的辨識負擔（不取樣）。
7. **刪除後**：刪除 George → 結束 Nous → 重新開啟 → George 看著說話。預期：只說「我在」。
8. **時序**（每條路徑至少 5 次，取中位數）：從 console 的 `[看著說話時序]` 記錄「在場確認」「面向確認」「互動啟動」「語音就緒」「問候決策」「首音」各自相對面向確認的毫秒；「面向開始」約在面向確認前 300 ms，「首次在場」約在在場確認前 500 ms（tracker 規則）。另以 log 的「連續證據 N 格／M ms，最新 K ms 前」看辨識是否來得及。比較稱名開與關時「互動啟動」的時間（應相同）。
9. **同時運作的負擔**（I7）：看著說話開始後到問候之前舉手掌，以及 Nous 回答時舉手掌各 10 次，記錄停止成功次數；`Activity Monitor` 記 Renderer／GPU CPU%。
10. **Keychain**：重新啟動 Nous 後第一次被看著說話辨識時，是否出現鑰匙圈提示（核心第一次取樣才載入 gallery）。

記錄格式：本目錄新增 `family-id-02-mac-YYYY-MM-DD.md`，每步「預期／實際／備註」，照實記錄失敗與模型實際說的話。

## 6. 未完成與疑慮

- **I12 未驗證**：模型是否一字不改照念、是否念出「（開場）」或指示、是否猜名，只能實測。若不照念，要改用確定文字的 TTS 並共用播音互斥與插話取消（14 §6），需另估工作。
- **API key 路徑的短句會經過 renderer**（ADR-0001 §2.1.1、§2.4.1）：審查修正後，頁面腳本要拿到名字必須先真的開一次看著說話的語音工作階段（開麥克風、顯示指示、可能計費），每個工作階段一次、每分鐘最多 3 次；要完全避免需由核心代送 `response.create`（ADR §11 待辦、需 Mac 實測）。
- **名字會跟著對話走**：念出後的逐字稿會進入 ChatGPT 方案路徑交辦給 Codex 的請求，模型也可能寫進任務標題；是否在交辦前遮掉問候那一則，留待 George 決定。
- **600 ms 仍未量測**：先開口的取消依賴伺服器的 `speech_started`／逐字稿在 600 ms 內回來；沒有本機語音活動偵測（14 §3）。
- **換人偵測靠「轉開／離開近距離」**：若換人時面向沒有中斷 300 ms 以上（`AttentionTracker` 遲滯 500 ms），頁面的世代不會加一；這時靠核心「同世代出現兩位家人就不稱名」，但「陌生人換成 George」在同世代內仍可能稱名（George 確實在眼前）。
- **黑名單只是盡力而為**：`speakableName` 擋不住所有像指令的名字（另限制最多 3 段、不能連續空白）；名稱只能經管理畫面原生確認登記，是主要防線。登記畫面會預覽怎麼念，不能念的名稱當下提示。
- **門檻未校準**：可能叫錯或認不出來；身分只用於稱呼，不作任何授權（Action Gate、確認卡都沒有讀身分，靜態檢查）。
- **Keychain 提示時機**：第一次在看著說話中被辨識時才載入 gallery，可能在那時跳出鑰匙圈提示。
- 時序只印到 DevTools console；Mac 上若打不開 DevTools，需改用錄影對照。
