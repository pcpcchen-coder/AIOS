# WK-01a 常駐喚醒聆聽底層驗證

日期：2026-10-31，Asia/Taipei。分支：`claude/wk-01`（基於 main `9778b41`，尚未提交與合併）。範圍：[17 §13.4](../17_Wake_Word_and_Speaker_Recognition_Plan_2026-10.md#134-交付批次與估時) 的 WK-01a（依 [17 §14.1](../17_Wake_Word_and_Speaker_Recognition_Plan_2026-10.md#141-2026-10-31-的分批決定wk-01) 由 WK-01 拆出）。規則見 [ADR-0003](../adr/ADR-0003-local-wake-and-voice-recognition.md)。

**這不是實機驗收，也沒有真正的喚醒偵測。** 本批只交付常駐喚醒聆聽的底層與接線；產品裡的偵測器在沒有引擎時照實回報 `runtime_missing`，不會開麥克風、也不會偵測。以下測試全部在雲端容器以 fixture（假的 MediaDevices、假擷取圖、假偵測器、假提示音）與假時鐘執行，**不是 Mac、不是麥克風、不是喚醒詞**。17 §13.2 的 W1–W12 都沒有在 Mac 上執行。

## 3. 設計選擇

1. **旗標關閉時逐位元組相同**：`tests/wake-flag-off.test.ts` 的快照是在 base `9778b41`、還沒有任何喚醒程式時先產生，之後的變更沒有更新它：`pageHeaders(false／true)`、實際回應的頁面標頭、`GET /api/settings` 的回應本文、選單列範本都相同。唯一刻意的改變是 `/wake-runtime/` 從 SPA fallback（200 回 index.html）改成 404。
2. **狀態以裝置事件為準**：`armed` 只代表正在取得；track 為 `live`、擷取圖接好、而且 worker 處理完第一塊樣本（`started`）之後才進 `listening_local`。
3. **一次性恢復字幕**只在自動恢復（App 啟動時偏好已開、睡眠或鎖定回來）成功時顯示；主視窗看不到時等 `visibilitychange` 變成 visible 再顯示一次。使用者在選單打開時用預設麥克風、不顯示恢復字幕，並記下真的在聽的那一支。
4. **暫停只在本次執行**：存在頁面記憶體，不寫 `wake.json`；暫停期間睡眠或鎖定回來不恢復。
5. **錯誤不重試**：`device_missing`、`device_ended`、`permission_denied`、`runtime_missing` 都停在 `error`，只有使用者操作或系統事件（開關、繼續、醒來、解鎖、Web Speech 結束、通話結束）才再試一次；不改用其他麥克風。
6. **觸發的終點**：偵測 → 防護 → 提示音 → 沒有取消而且仍在 `listening_local` → `onTrigger(WakeTrigger)`。預設只顯示字幕「聽到了」、繼續聆聽，不開通話。WK-02 的接口：`WakeController.setTriggerHandler`、`lease()`／`releaseLease()`、`NoVoiceWatchdog`、`power()`、`webSpeech()`。
7. **無人聲計時是音量門檻，不是 VAD**：`NoVoiceWatchdog` 沿用即時語音開口偵測的 RMS 門檻（0.03，連續 300 ms，未校準），分不出人聲與電視、音樂。WK-02 才接到通話。
8. **聽覺區不連動**：區域活動的收音來源仍只有三種語音模式；小麥克風圖示是獨立的 DOM 元素，`listening_local` 以外隱藏。

## 4. 與規劃不同之處

- 「只有 `front-end.ts` 呼叫 `getUserMedia({ audio })`」在旗標開啟時成立。旗標關閉時依要求保留原本的 `browserRealtimeDeps().getMicrophone`（`src/realtime.ts:891`），所以靜態測試另外釘住這唯一一行；鏡頭管線的 `getUserMedia` 是 `audio: false`。
- worker 檔名是 `wake-worker.ts`（不是 17 §12 的 `kws-worker.ts`），避免建置產物的檔名含 kws（`tests/wake-privacy.test.ts` 會擋）。
- 選單列的狀態、原因與文字在 `desktop/settings-menu.mjs` 與 `desktop/preload.cjs` 各有一份（App 直接執行這兩個檔，不能載入 `.ts`），測試核對與 `shared/wake.ts` 完全相同。
- `device_id` 在開關關掉時一併清掉：下次由使用者明確打開時用預設麥克風。App 重開時偏好開著但從沒記到裝置（從未真的在聽），就用預設麥克風。

## 7. 風險與限制

- **沒有真正的偵測**：WK-01a 的任何結果都不能當成喚醒能力的證據；W5、W6 需要 WK-01b 與 Mac 客廳。
- **renderer 內的程式仍可讀到麥克風**：與 ADR-0003 §2.3 第 3 點相同；靜態測試只能擋字面寫法。
- **開關只在主程序**（審查 M2 修正）：`POST /api/settings/wake` 收到 `wake_listen: true` 一律 403，頁面只能記下 `device_id` 或關掉；打開只能由 App 主程序在原生說明之後經 `NousHandle.wake.setListen`（同一行程，不經 HTTP、沒有 preload API）。瀏覽器版因此不能打開常駐聆聽。`POST /api/settings/camera` 有同一類問題（頁面腳本可以打開鏡頭），列為另一個已知事項，本批不改。
- **從語音模式直接切到即時語音**（審查 m5 修正）：Web Speech 結束後的重新取得延到下一個 macrotask，同一輪就來的租用會取消它，不再同時有兩個 `getUserMedia`；W8 仍要在 Mac 觀察。
- **背景 AudioWorklet 與提示音的自動播放**都沒有在 Electron 驗證；`capture.ts` 把 worklet 接到音量 0 的輸出，讓它持續被排程，是否必要也待 Mac 確認。
- **頁面重新載入**會忘記「暫停聆聽」（存在頁面記憶體），並視為 App 啟動而自動恢復。
- `NoVoiceWatchdog` 是音量門檻，不是 VAD；電視開著時可能永遠不逾時。
- 1.5 秒播音尾巴、3 秒去重、350 ms 提示音、RMS 門檻都是未校準的起點值。

## 8. 獨立審查後的修正（2026-10-31）

獨立審查沒有阻擋項，有 2 個 major、9 個 minor 與一些小問題，全部已修正；審查者的探測案例已改寫成回歸測試（`tests/audio-front-end.test.ts`）。

| 編號 | 問題 | 修正 |
|---|---|---|
| M1 | `releaseLease()` 會停掉所有租用：過時的工作階段晚到的歸還會停掉新通話的複製品 | `releaseLease(stream)` 只歸還那一份；`RealtimeDeps.releaseMicrophone(stream)` 帶自己的串流；頁面的保險歸還（`releaseAllLeases`）只在沒有任何進行中或開始中的通話時執行。新增同時兩份租用的測試 |
| M2 | 頁面腳本可以 `POST {wake_listen:true}` 略過原生說明 | 打開只能由 App 主程序經同一行程的 `NousHandle.wake.setListen`（沿用 identity／memory 由主程序直接呼叫核心的做法）；HTTP 收到 `wake_listen: true` 一律 403，頁面只能記下 `device_id` 或關掉。鏡頭的 `POST /api/settings/camera` 有同一類問題，列為另一個已知事項，本批不改 |

| m2 | 引擎缺少時每通電話結束後都重複錯誤字幕 | 同一個原因只說一次，直到真的聆聽或關掉 |
| m3 | worker 可能在以 0 覆寫之前就被 terminate | worker 清空並釋放偵測器後回 `closed`，主執行緒等它（最多 100 ms）才 terminate |
| m4 | 靜態隱私測試可被繞過 | 每個 `postMessage` 都對固定白名單；禁止 `self.`（只允許 worker 進入點的固定寫法）、`globalThis[`、`Reflect.`、`eval(`、`new Function`、`importScripts`、`window[`；`new URL(` 只能指向 wake worker |
| m5 | 語音模式直接切到即時語音時可能同時有兩個 `getUserMedia` | Web Speech 結束後的重新取得延到下一個 macrotask，同一輪的租用會取消它 |
| m6 | 旗標開著但沒有引擎時 CSP 也放寬 | 只有引擎核對通過時才加 `'wasm-unsafe-eval'`；旗標關閉的快照不變 |
| m7 | worklet 沒有指定單聲道混音 | `channelCountMode: "explicit"`、`channelInterpretation: "speakers"` |
| m8 | ADR-0003 開頭仍寫 `AudioFrontEnd` 與 worker 不存在 | 中英兩版已更新 |
| m9 | 通話中核心關掉旗標會停掉通話用的複製品 | 等通話結束才結束常駐聆聽 |
| 小問題 | 註解指向不存在的測試檔；停用時沒有重設防護；選單在頁面回報前寫「準備中」；載入期間在選單打開會顯示「已恢復」；裝置中斷與引擎載入失敗的字幕寫「沒有開啟」 | 註解改指實際檔案；停用時 `WakeGuard.reset()`；回報前寫「尚未回報」；先套用第一次看到的設定再套用最新的；這兩種原因改寫「常駐喚醒聆聽已停止：…」 |

`capture.ts` 的等待與 `channelCountMode` 只有靜態檢查與型別檢查，沒有在瀏覽器執行過（Mac gate）。
