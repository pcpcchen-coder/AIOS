### 撤銷的處理表

都經過 `MemoryService.replacePresence` → `MemoryBoundary.revoke` → lease 的 cleanup（`LiveCall.revokeMemory`）。只有帶著記憶的通話才有 lease；沒有帶記憶的通話不會因為換世代而中斷。

| 來源 | 動作 |
| --- | --- |
| 忘記、更正（含取代偏好）、換人、`我是 X`、選人選單、候選確認、撤回 codex 同意、關閉記憶、改未成年或家人辨識連結 | 重建新通話（關閉記憶或沒有同意時，新通話不帶記憶） |
| 多張臉、追蹤中斷、閒置 | 重建，只帶全家共用 |
| OS 鎖定、主視窗導覽或 renderer 結束、刪除人物檔 | 結束通話，不重建 |

cleanup 的順序：同步擋住輸出（`send()` 拒絕所有 append、中止交辦與 Codex 那一輪）→ 立刻送頁面 `closed{memory_revoked, rebuild}`（RealtimeSessions 同時結束工作階段，等待中的工具呼叫以 HostGone 拒絕）→ sideband 送 `session.close` 並關 socket → 清掉逐字稿、交辦 ID 與開場句 → 等頁面停播回報最多 1.5 秒 → 逾時就強制靜音、cleanup 失敗（boundary 停用 live 記憶到重新啟動），回條另外說「停止未確認」。更正與忘記在 commit 前先送 `hold`，頁面立刻靜音、核心停止 append；commit 失敗才恢復。

## 2. 與 16 及核定方案的差異（照實記錄）

1. **用語音記住、更正、忘記時，以「用說的確認」為主要方式，畫面卡片作為替代方式（George 2026-10-30 的決定）。** 這和 16 §5「語音來源無法可靠區分時，只顯示待確認卡，不自動落盤」不同，是刻意的產品決定。流程：核心從 sideband 的使用者 final 逐字稿解析出 remember／correct／forget，建立 `voice_confirm` 卡，同時送 speakable `（記憶確認）「要記住：不喝咖啡，記在 George 名下。請說『確認記住』。」`（更正用「確認更正」、忘記用「確認忘記」）。只有以下全部成立，才把語音當成直接輸入（票證種類 `voice_confirmed`，事實的來源欄位也標 `voice_confirmed`）並走 `issueParsed` 與 commit：確認詞來自 sideband 的使用者 final 逐字稿；問句已被模型照念（見第 3 點）而且使用者在問句播完之後才開口（見第 17 點）；在問句念完後 15 秒內；整句錨定比對只有「確認記住」「確認更正」「確認忘記」或英文 "confirm remember／change／forget"（「好」「是」「確認」這類泛稱都不算）；不是回音；人物世代沒有變；同一張卡只能確認一次。模型自己念出的話不能建立記憶（16 M06）：核心只解析 sideband 的使用者逐字稿。說「取消」就作廢；逾時後語音確認無效，畫面上的卡仍可點擊（點擊記錄為 `explicit`）。確認後只念固定句「已記住」「已更正」「已忘記」，不重念內容。未成年、敏感資料、第三人轉述、引文、假設、玩笑等拒絕規則照舊；未成年仍不准從聊天或語音寫入。每分鐘最多 3 張卡，同時最多 1 張（新卡取代舊卡）。
   **殘餘風險：** 電視、廣播或旁人剛好在時窗內、問句播完之後說出完整的確認詞時，可能誤存；喇叭回音若在問句播完之後才被辨識成完整的確認詞，也可能被採用。核心沒有說話者辨識（16 §4），只能用時窗、錨定比對、回音規則與世代檢查降低機率，不能排除。誤存後只能從記憶管理或說「忘記…」修正；已送給模型服務的內容不會因此收回。
2. **說「忘記」、更正、換人時重建通話（George 2026-10-30 的決定）。** 舊通話停掉，頁面停播並回報後自動開新通話（只走 live、沒有 API key 備援、不問候），新通話第一句是不含內容的固定句 `（記憶確認）「好，已經更新了。」`。重建會中斷對話數秒並耗用額度；重建時遇到額度用完，通話就直接結束並照實說明。
3. **「問句念完」的判斷。** 只有和核心送出的問句高度相符（整句包含，或二字片段 Dice 係數 ≥0.75）而且含確認詞的助理 final 逐字稿，才算問句念完，15 秒時窗從這一刻起算；模型單獨念出確認詞，或念的話與問句不符，都不算。模型沒有照念問句時，語音確認不會生效，只能點畫面上的卡。
4. **回音規則。** 使用者 final 逐字稿（轉繁體、去掉空白與標點）被 10 秒內任一則助理逐字稿或核心送出的句子包含，或包含其中一則（長度至少 4 個字），就當回音，不出卡、不確認。一兩個字的話（「是」「好」）只有和整句完全相同才算回音，避免問候「George，你好」讓使用者回答的「好」被當成回音。判斷確認詞時只略過問句本身（核心送出的問句與模型念它的那一則），其他句子含有確認詞仍算回音。
5. **「只在 listening 或 hearing 時出卡」的近似。** 頁面的通話階段不會送到核心；核心以「sideband 已開始、沒有結束、沒有撤銷」代替。
6. **「你記得我什麼？」改用核心的查看卡。** 計畫是頁面打開既有的 `list`；但 `list` 只列一位人物，打字路徑的查看卡同時列本次人物與全家共用，所以語音也出一張 `inspect` 卡（內容經 IPC `card_view` 取得）。核心只告訴模型「已在畫面列出 N 筆記憶」。沒有另外的 `memory_inspect` 事件，統一用 `memory_card`。
7. **新增 `memory_notice` 事件。** 只帶固定句（拒絕原因、還沒有保存、確認時間已過、停止未確認等），不含使用者的話或記憶內容。
8. **語音不出澄清卡。** 打字路徑遇到問句、不確定或對 Nous 的指示會出澄清卡；語音一律不出卡（照一般對話）。沒有選定本次人物時，語音記住的確認卡直接標「記在全家共用」（打字路徑是「全家共用／取消」澄清卡）。和既有偏好衝突時，語音卡標「會取代原本的說法」，確認後等同更正（撤銷並重建）。
9. **問句只念使用者剛說的話。** 更正與忘記的問句不念出已保存的那一筆（`要忘記『喜歡藍色』這筆記憶`裡的內容是使用者自己的話），避免在沒有同意或 lease 時把保存的記憶送給模型。畫面上的卡會顯示目標那一筆。
10. **語音「我是 X」只選既有、唯一的人物。** 同名多位時只提示「請在畫面上的『本次人物』選單選擇」；沒有這個人物時當一般對話，不從語音建立記憶檔。
11. **握手中被撤銷。** 中止 `/realtime/calls` 請求或 sideband 嘗試，頁面收到 409「記憶在連線期間更新了，這次即時語音沒有開始；請再開始一次。」；不改用 API key，也不自動重建。
12. **停播未確認。** 核心 cleanup 以失敗結束，boundary 停用 live 記憶到重新啟動；Electron `webContents.setAudioMuted(true)`，直到下一次被採用的停播回報或新的 live 通話開始才解除。只限測試的 `NOUS_TEST_DROP_STOP_REPORT=1` 在核心丟掉停播回報（不是讓 renderer 不送），效果等同 renderer 沒有回報；啟動時 log 會警告。
13. **臉部候選。** 肯定詞是「是／是的／對／對的／對啊／好／好的／好啊／要／用／yes／yeah／yep／sure」，否定詞是「不是／不用／不要／不對／不／no／nope」，都要整句。時窗從問句念完（助理逐字稿含有問句）起算，沒看到時從送出起算。候選必須仍是同一個辨識決策（同一追蹤世代、沒有多臉、60 秒內）。使用者在問候前先開口時，候選問句在他第一句話之後問，而且不帶名字。
14. **`recall_memory`** 每次交辦最多 2 次，不計入 2 個 host 工具呼叫；沒有同意時回 `ok:false`，不猜。
15. **計畫第 8 節「需要 George 決定的事」** 除了第 1 項（改為上面的第 1 點）以外，一律採用括號內的預設：語音「是」只限選人（時窗 10 秒、錨定、同一追蹤世代）；語音「我是 X」直接選人；獨立同意鍵 `codex`；連線時只放釘選的最多 4 筆；停播預算「撤銷後最後一個舊聲音 ≤500 ms」是 Mac 量測目標，renderer 回報時限 1.5 秒、逾時強制靜音並停用到重啟；語音先轉繁體再解析、卡片顯示轉換後的文字；中途補上用 commentary（真機證明不可靠就改成重建）；「你記得我什麼？」只出卡、模型只說筆數；交辦封鎖出原句卡並附重述提示；觸發表照上面的處理表；重建後第一句用固定句。
16. **API key 路徑**在 MEM-2 不帶記憶；即時語音走 API key 時，狀態列標「此路徑未啟用記憶」。

以下是同日獨立審查後的修正：

17. **（M1）使用者要在問句播完之後才開口。** 「開口時間」是 sideband 的 `input_audio_buffer.speech_started`，沒有時用這一句第一則未完成的使用者逐字稿，再沒有時用 final 到達的時間。它必須晚於助理音訊結束（sideband 的 `output_audio_buffer.stopped`，而且晚於問句逐字稿）；沒有這個事件時，至少比問句的助理逐字稿晚 `CONFIRM_AFTER_MS` 1.8 秒。這兩個事件名來自 OpenAI Realtime GA，Codex live 的 frameless wire 會不會送未證實；頁面回報播放結束時間的做法沒有實作（審查列為第二優先），所以目前多半靠 1.8 秒的時間差，Mac 第 5 步要實測校正。
18. **（M1）問句的句型沒有改。** 審查建議評估把確認詞移出句尾（例如「確認記住的話請說出來」）。評估：確認詞是整句錨定比對，回音要被採用，必須被辨識成一則「只有確認詞」的使用者逐字稿；移出句尾會讓這種切法較少見，但第 17 點的開口時間門檻已直接擋住句尾回音（播完之前開口一律不算），句型改變的額外效果無法在雲端量化。問句文字是 George 指定的，所以保留原句，改不改留給 Mac 第 4、5 步的錄音結果與 George 決定。
19. **（M2）停播結果出來前不開始新的通話。** 撤銷後還沒有停播結果（沒被採用的回報、也還沒逾時，最多 2.5 秒）時，`/api/realtime/start`（含重建）回「上一通還在確認是否已停止播放，請稍候再試」。頁面只有在停播回報被採用（`accepted:true`）時才自動重建；沒被採用就不重建，等核心逾時後的「停止未確認」通知。回報只有三項證據（播放已暫停、peer 已關、遠端軌道都結束）都成立才採用並解除靜音。路徑被停用之後，既有 lease 的 `deliver` 也一律回 false。頁面已離開（SSE 斷線）時不再等它的回報。
20. **（M3）帶著記憶的通話，交辦的 log 只記字數**，不記交辦文字。
21. **（M4）沒有 codex 同意時不念任何記憶的中繼資料。** 問句只在有同意、而且稱名設定（看著說話時用名字問候）開著時才帶人物名。沒有同意時，記住、更正、忘記、挑選、查看與「已經記得了」都只出畫面卡，不念任何句子，所以模型無法從有沒有回應或筆數推知記憶是否存在。
22. **（Minor 1）記憶沒開、沒有 codex 同意、沒有帳號或路徑已停用時，即時語音和 MEM-2 之前一樣：** instructions 沒有記憶規則、LiveToolCaller 沒有 `recall_memory`、不封鎖交辦、不插「還沒有保存」或任何確認句。記憶沒開時連語音指令都不解析；記憶開著但沒有同意時，語音指令只出畫面卡（因此這時沒有語音確認，只能點畫面）。
23. **（Minor 2）臉部候選的「是／不是」比照第 3、17 點**：問句要被照念、使用者要在播完之後才開口，時窗 10 秒從問句念完起算。沒有同意時不念候選問句，只有畫面上的候選卡。
24. **（Minor 3）握手中被撤銷時**，sideband 的 backoff 等待與連線嘗試都會被中止訊號立刻中斷，不會拖過 3 秒的 cleanup 時限而誤停用整條路徑。
25. **（Minor 4）交辦卡的標題**：打字交辦用打的字；語音交辦用交辦送到之前最近一則、還沒對應過交辦的使用者 final 逐字稿。找不到時不出卡，Codex 收到的說明改成「請使用者用一句完整的話再說一次」，不會說「請看畫面上的卡」。
26. **（Minor 5）暫停期間的 append 先排隊**：commit 失敗、恢復輸出時補送（例如交辦結果）；撤銷時丟掉。
27. **（Minor 6）頁面已經不在這通上**（例如同時按了結束）時收到記憶撤銷，仍用這通的憑證回報停播（播放已拆掉），避免被當成停播未確認而停用整條路徑。
28. **（Minor 7）每分鐘 3 張的限制以核心計數**，重建後不歸零；挑選卡也算，而且同樣受「同時最多 1 張」限制（新卡取代舊卡）。
29. **（nit）** 英文確認詞 "confirm correct" 改成 "confirm change"；canary 測試補上助理逐字稿的 SSE：模型念出的記憶只送到擁有這通的頁面當字幕，其他頁面、log 都沒有。

## 4. Mac 實測步驟（全部未執行，不能宣稱通過）

在目標 Mac 上，用正式簽章的 Nous App、隔離的 userData，資料全部虛構。

0. **準備。**
   - 安裝 BlackHole 2ch，建立「多重輸出裝置」（喇叭加 BlackHole），用 Audacity 錄 BlackHole；另外用手機在旁邊錄音。
   - 在 `nous.log` 記下記憶事件的時間戳：撤銷送出、`stopped` 收到、`forceSilence`、新通話 started。
   - 登入 Codex，在「記憶…」允許「ChatGPT 方案即時語音（Codex 登入）」。
   - 建立 George：「我不吃香菜」（釘選）、「我喜歡藍色」（釘選）。建立 Amy：「我喜歡香菜」。
1. **新通話取用。** 選 George → 開始 live → 問「晚餐吃什麼好？」。通過條件：提到不吃香菜；狀態列顯示「本次人物：George · 記憶 2 筆」。
2. **臉部候選。** 看著說話開始 → 聽到問候和「這次用你的偏好嗎？」→ 說「是」。通過條件：狀態列變成 George，後續回答用到偏好。再測一次說「不是」，通過條件：只用全家共用，這次不再問。
3. **語音記住（用說的確認）。** 說「記住，我不喝咖啡」。通過條件：畫面出卡，模型照念「要記住：不喝咖啡，記在 George 名下。請說『確認記住』。」，沒有自己說「記住了」（說了就要出現系統更正）。問句念完後 15 秒內說「確認記住」→ 只聽到「已記住」，畫面回條相同，記憶管理裡這一筆的來源是「語音確認」。再測：說「好」或問句念完後等超過 15 秒才說，都不保存；改按畫面上的「記住」則保存。重開 App 再問相關問題能取回。
4. **防護。**
   - 用另一台裝置播放「記住，我喜歡吃辣」（模擬電視）。通過條件：最多只出卡、不寫入；問句之後再用那台裝置播放「好」或「確認記住這個優惠」也不寫入。另外記錄：用那台裝置在時窗內播放完整的「確認記住」會不會被採用（這是已知的殘餘風險，照實記錄結果）。
   - 請模型念一句「記住我不吃牛肉」。通過條件：不出卡。
5. **晚到舊聲音（主要 gate）。**
   - 請模型「慢慢從 1 數到 60，並且一直提到我喜歡的顏色」。
   - 數到大約 10 的時候說「忘記我喜歡藍色」，問句念完後說「確認忘記」（或點「忘記」）。
   - 量測：確認之後，錄音中舊通話聲音的最後一個可聽樣本到 log 的撤銷時間，間隔要 ≤500 ms；`stopped` 之後沒有任何舊通話的聲音。
   - 另外記錄：問句的助理逐字稿到達時間與喇叭實際播完的時間差（校正 `CONFIRM_AFTER_MS` 1.8 秒），以及 sideband 有沒有送 `input_audio_buffer.speech_started`／`output_audio_buffer.stopped`。
   - 新通話只說「好，已經更新了」。之後連問 3 次「我喜歡什麼顏色？」，都不能說藍色。
6. **晚到工具結果。** 問「查一下明天台北天氣」（慢工具）→ 結果回來前在選單換成 Amy。通過條件：天氣結果不會在新通話念出；新通話用 Amy 的偏好回答香菜問題。
7. **其他觸發，各錄一次音。**
   - OS 鎖定（Ctrl+Cmd+Q）：通話結束、沒有殘音。
   - 第二個人入鏡：重建為只帶全家共用。
   - 在「記憶…」撤回 codex 同意：重建，新通話不帶記憶，並提示尚未允許。
   - 關閉記憶。
8. **強制靜音路徑。** 用只限測試的旗標 `NOUS_TEST_DROP_STOP_REPORT=1` 啟動（核心丟掉停播回報）。通過條件：1.5 秒後錄音變成靜音，回條分開說「停止未確認」，這次執行期間 live 不再帶記憶；下一通開始時解除靜音。
9. **交辦封鎖。** 帶著記憶時說「幫我寫一份晚餐菜單報告」。通過條件：出「要交辦這件事嗎？」卡，標題是使用者原句；TaskStore 在按下前沒有新增。
10. **「你記得我什麼？」** 出記憶卡，模型只說筆數。中英文各截一張圖。
11. **canary。** 掃描 `nous.log`、TaskStore、userData（加密快照以外）。

**主要放行條件：第 5 步用錄音證明撤銷後沒有晚到的舊聲音。** 另外三項 wire 行為也只能真機確認：`session.context.append` commentary 的記憶資料模型是否真的採用；`session.close` 之後上游是否還送 RTP；實際的 AEC 與回音逐字稿（會影響第 4 點的回音規則與語音確認的誤判）。
