# Architecture restructuring S8: single source for the tool list (2026-11-10)

Related document: [23 Architecture review and restructuring plan](../23_Architecture_Review_2026-11.en.md), §P1-2 and S8 in §3; George approved S6–S9 on 2026-11-10. This batch only folds lists and numbers that were declared several times into one place. **The goal is zero behaviour change.** Everything here is type checking and automated fixture tests in a cloud container. **There was no real voice call; this is not a product gate and not a Mac/Pi hardware acceptance.**

## 1. Environment

- Branch `claude/arch-s8-tool-names`, based on main `1b61d08` (which already contains `show_search_result` from PR #140).
- Linux cloud container, Node.js v22.23.4, vitest 5.0.3, TypeScript 7.0.2, Vite 8.3.4. `prototype/ambient-shell/node_modules` is a symlink to the main checkout and is not committed.
- Codex Responses, the page tool executor and the home hub are fakes inside the tests; no microphone, no OpenAI connection, no real account.

## 2. Inventory before the refactor

All paths below are under `prototype/ambient-shell/`.

### 2.1 The six lists

| # | Location | Form | Order | Where order or membership is observable |
|---|---|---|---|---|
| A | `shared/realtime-route.ts` `HostToolName` | type union | `web_search`, `show_search_result`, `delegate_task`, `get_tasks`, `end_conversation`, `home_status`, `home_control`, `set_voice_volume`, `set_day_night` | Type only; does not exist at runtime |
| B | `shared/voice-commands.ts` `RealtimeToolName` | type union | Same as A | Type only; it is the key type of `ASK_THE_AI` |
| C | `server/live-tool-caller.ts` `HOST_TOOLS` | module-private array (not exported) | Same as A | Used only in `HOST_TOOLS.includes(name)`: order is not observable; membership decides whether a name called by the model goes to the page or gets "這條路徑沒有這個工具" |
| D | `server/realtime-routes.ts` `HOST_TIMEOUT_MS` | `Record<HostToolName, number>` | `home_control`, `home_status`, `web_search`, `show_search_result`, `delegate_task`, `get_tasks`, `end_conversation`, `set_voice_volume`, `set_day_night` | `Object.values()` for the maximum (`MAX_HOST_TIMEOUT_MS`) and `HOST_TIMEOUT_MS[name]`, neither depends on order; the keys were already checked by the type at compile time |
| E | `shared/voice-commands.ts` `ASK_THE_AI` | object keyed by B | `end_conversation`, `set_voice_volume`, `set_day_night`, `get_tasks`, `web_search`, `show_search_result`, `delegate_task`, `home_status`, `home_control` | **Observable**: the `Object.keys()` order is the row order of "可以問 AI" in the command table (`/help/commands` and the generated block in the prototype README) |

In addition, `executeRealtimeTool(name: string, …)` in `src/realtime-tools.ts` is a chain of `if (name === "…")` (not a `switch`), one branch for each of the 9 names.

The six lists have **exactly the same members** (9). A, B and C share one order; D, E and F each have their own.

### 2.2 Tools that were never in the list

| Tool | Where | Why it is not in `HostToolName` |
|---|---|---|
| `recall_memory` (`RECALL_MEMORY_TOOL`) | Added by `buildRealtimeTools()` after the home tools when `caps.memory` | Executed by core itself (`LiveToolCaller` / `apikey-call.ts`), does not go through the page, has no page timeout |

| MCP servers (`type: "mcp"`) | `caps.mcp` | Executed on the OpenAI side; unavailable on the ChatGPT plan route, where `liveCallerTools()` removes them |

All of these differences are preserved; none was merged into the single list.

### 2.3 Length limits on home arguments

| Location | Content |
|---|---|
| `server/app.ts` `/api/home/status` | `target.length > 100` or `metric.length > 40` → 400 `target or metric is too long` |
| `server/app.ts` `/api/home/control` | `target.length > 100` or `command.length > 40` → 400 `target or command is too long`; string `value.length > 40` → 400 `value must be a short string, a number or a boolean` |
| `server/integrations/adapters/home.ts` `inputSchema` | status: `target` `maxLength: 100`, `metric` `maxLength: 40`; control: `target` 100, `command` 40, `value` 40 |
| `server/realtime.ts` `HOME_STATUS_TOOL` / `HOME_CONTROL_TOOL` | **No length limit at all** (the schemas contain no `maxLength`) |

**Discrepancy with 23 §P1-2**: the review says the home argument limits are stated "in three places"; only two places actually state numbers, and the schema sent to the model never had `maxLength`. The numbers in the two places agree (100/40/40/40); there are no conflicting values. The length of `confirm_id` (6–69 in `adapters/home.ts` versus `/^home_[\w-]{1,64}$/` in `app.ts`, that is 5+1 to 5+64, so the two match) is not a model tool argument and was not touched in this batch.

## 3. What was done

| List | Before | After |
|---|---|---|
| A `HostToolName` | hand-written union | `export const HOST_TOOL_NAMES = [...] as const` (same order as the former union); `HostToolName = (typeof HOST_TOOL_NAMES)[number]` |
| B `RealtimeToolName` | hand-written union | `export type RealtimeToolName = HostToolName` (type-only import of `./realtime-route.ts`) |
| C `HOST_TOOLS` | hand-written array | `const HOST_TOOLS: readonly HostToolName[] = HOST_TOOL_NAMES` |
| D `HOST_TIMEOUT_MS` | `Record<HostToolName, number>` | Unchanged (values and key order untouched; one comment line added). A missing or extra key already failed to compile |
| E `ASK_THE_AI` | `{ [T in RealtimeToolName]: AskTheAi }` | Unchanged; its key type now follows `HOST_TOOL_NAMES`, so a missing row fails to compile. The row order is still decided by this object |
| F tool schemas | each has its own `name` | Unchanged (only a comment on `REALTIME_TOOLS`). The set of names is compared by tests at compile time and at runtime |
| `src/realtime-tools.ts` | `if` chain | **Not modified.** The parameter is a `string` and there is no `switch` to attach an exhaustiveness check to; a test reads the source and compares the branch names instead |
| Home limits | numbers written in two places | `shared/home.ts` gains `HOME_ARG_MAX = { target: 100, metric: 40, command: 40, value: 40 } as const`; the schema in `adapters/home.ts` and the five comparisons in `app.ts` reference it. The schemas in `server/realtime.ts` do not (adding `maxLength` would change the JSON sent to the model) |

Files changed: `shared/realtime-route.ts`, `shared/voice-commands.ts`, `shared/home.ts`, `server/live-tool-caller.ts`, `server/realtime-routes.ts` (comment only), `server/realtime.ts` (comment only), `server/integrations/adapters/home.ts`, `server/app.ts`; new `tests/realtime-tool-names.test.ts` and its snapshot.

**What to change when adding a page tool** (it is not a one-place change; the hand-written `HOST_TOOLS` list is gone, the rest still has to be added):

1. Add the name to `HOST_TOOL_NAMES` in `shared/realtime-route.ts`.
2. `tsc` then forces the entries in `HOST_TIMEOUT_MS` in `server/realtime-routes.ts` and `ASK_THE_AI` in `shared/voice-commands.ts` (run `npm run docs:commands` afterwards).
3. You must add yourself: the tool schema (and rule text) in `server/realtime.ts` and the branch in `src/realtime-tools.ts`. Without them `tests/realtime-tool-names.test.ts` fails (the schema also fails the `expectTypeOf` under `tsc`).
4. Update the characterization lists in `tests/realtime-tool-names.test.ts` (`CANONICAL`, `TIMEOUT_KEY_ORDER`, `ASK_ORDER`, `MODEL_ORDER`, the timeout values) and the snapshot.

**Differences from the text of 23 §3**:

1. The plan says the limits "keep only the `adapters/home.ts` schema, referenced by `realtime.ts` and `app.ts`". They actually live in `shared/home.ts`: `app.ts` already imports `adapters/home.ts`, but keeping the numbers in shared avoids making the HTTP layer depend on an integration Adapter for a number. `realtime.ts` does not reference them, for the reason in §2.3.
2. The plan estimated 4 files; 8 source files changed (2 of them comment only).
3. Module dependencies: `shared/voice-commands.ts` gains one type-only import of `shared/realtime-route.ts` (inside shared). The metrics script still reports 0 cross-layer imports and 4 import cycles, and `tests/architecture.test.ts` passes unmodified.

## 5. Limits

- Fixture tests in a cloud container only: no real voice call, the tool table was not sent to OpenAI or Codex, and there was no real hub. "The JSON sent to the model is unchanged" compares the strings core produces; it is not an observation of the request received upstream.
- The 7 capability sets are hand-picked representatives, not an exhaustive enumeration of every switch; the integration tool is a fake spec written in the test, not the real Registry's `app__tv__` / `app__timer__` / `app__alarm__` (those rule texts are covered by existing tests).
- `HOST_TOOLS` is not exported, so its members were observed through behaviour; its order never had external behaviour and is not tested.
- The page executor is compared by reading its source with a regular expression: this only detects "one name missing or one extra", and does not prove that a branch does the right thing (the existing `realtime-tools` tests are responsible for that).
- The checks that read source text (the branch names in `src/realtime-tools.ts`, and the `HOME_ARG_MAX.` references in `app.ts` and `adapters/home.ts`) are deliberately brittle characterization checks: rewriting the code makes them fail, and a person then has to judge whether things are still consistent.
- The test's `freePort()` helper (open a port to probe, close it, then listen) has the same race as the 17 other files using the same helper (under `tests/`, fixtures included): another process can take the port in between. The one full-suite run mentioned in §4.3 that had 1 failing test, whose name was not recorded (docs were being edited and the bilingual check was running at the same time), may have been caused by this; that is not confirmed, and it was not reproduced in 4 later full runs.
- The parameter of `src/realtime-tools.ts` is still a `string`, with no compile-time exhaustiveness check; changing it to `HostToolName` would touch the callers on both page voice paths and is outside this batch.
- The home tool schemas in `server/realtime.ts` still have no `maxLength`: when the model sends an over-long argument, `/api/home/*` answers 400. Whether to tell the model the limits is a behaviour change and is not done in this batch.
- This batch does not address the other items of 23 §P1-2 (the duplicated methods of the two page paths, and `recall_memory` / `delegate_task` implemented once per core path).
- A passing full suite is only a code check, not G0–G3 or any Mac/Pi gate. The number of skipped tests varies by environment.
