# Pi 終端的家人辨識（臉與聲音）與記憶選人畫面驗證

日期：2026-11-05。分支 `claude/pi-family-recognition`（基於 main `6072f6c`）。狀態：**程式與 Linux 雲端自動測試完成（含同日審查後的修正）；Pi、立體鏡頭、真模型與已登記家人都未實測。**

## 需求與決定（George，2026-11-05）

家人辨識要能在 RPI 上用，鏡頭與聲音都要。George 的決定：

1. Pi 接和 Mac 同款的立體鏡頭。
2. 一律允許 Pi 使用，不加開關，也不做配對。
3. 「正在用 X 的記憶」與「不是我」的畫面這批一起做。

## 做法

| 部分 | 行為 |
|---|---|
| 計算位置 | 臉部（YuNet＋SFace）與聲音（CAM++）的特徵本來就在頁面算，模型由 Mac 核心以網址提供。Pi 頁面算好特徵後送到 Mac 核心比對；**只傳特徵數字，不傳影像或聲音**。比對與加密保存都在 Mac 核心，頁面拿不到分數 |
| 辨識通道 | `POST /api/terminal/identity`，內容 `{terminal, request}`。只接受 `ambient_status`、`ambient_probe`、`greeting`、`voice_probe`、`call_voice`；其他（開管理畫面、列名單、登記、刪除、校正、試認等）一律 403。驗證和 Mac IPC 用同一份程式（`shared/identity-validate.mjs`），錯誤訊息相同。核心以 `userInitiated: false` 處理 |
| 記憶通道 | `POST /api/terminal/memory`。只接受 `status`、`suspend`、`select`（不能帶管理用 token）、`card_view` 與 `card_answer`（只限臉部候選卡，回答只能是「不要」）。回應用允許清單挑欄位：狀態只有記憶狀態（ready 等）、本次人物、每位人物的 ID 與名字；`select`／`card_answer` 另有回條與「清除歷史」旗標。記憶內容、卡片、對話、建議、記憶筆數、未成年與臉部連結旗標、服務帳號與同意、建議開關都不送。打字聊天帶記憶、記憶建議、管理都仍只在 Mac |
| 終端名稱 | 請求帶 kiosk 網址的 `terminal`（例如 `rpi4`）；終端機頁面另外在每個 API 請求帶 `X-Nous-Terminal: <名稱>` 標頭（不帶或不合法時算 Mac 主視窗 `main`；`main` 不能當終端機名稱）。兩者都只用來分開各頁面的辨識與記憶候選，不是安全驗證：Mac 本機任何 HTTP 用戶端（不只頁面）都能呼叫這些路由、帶任何名稱（George 選「一律允許」） |
| 分開記的狀態 | 核心每個頁面各自保存取樣證據、最近一次臉部比對、喚醒聲音、通話中聲音、多張臉時間與各自的速率限制；最多記 8 個頁面，超過時丟掉最久沒用的終端機，Mac 主視窗不會被擠掉。所有終端機另有一份合計的速率限制（取樣每秒 6 次、喚醒聲音每秒 4 次、通話中聲音每秒 2 次，和改版前的全核心上限相同），換名稱繞不過；格式錯誤的請求不建立頁面、也不佔速率。喚醒後放寬「看著說話」設定的時窗只對開始那通喚醒的頁面有效。問候的速率限制與「每次互動只問候一次」仍是全核心共用。Mac 開著家人辨識管理畫面時，所有頁面的辨識都暫停（沿用原規則） |
| 記憶候選 | 記憶預設選人只用發問頁面自己的辨識結果：Mac 的打字聊天只看 Mac 鏡頭的候選；即時語音通話只看開始那通的頁面（核心從 `/api/realtime/start` 的標頭知道）。Pi 看到的臉不會替 Mac 選人，反之亦然 |
| 記憶選人 | 核心只有一個「本次人物」，並記住是哪個頁面選定的。別的頁面的鏡頭事件（多張臉、追蹤中斷）與通話中聲音不一致，不會暫停或撤銷它；選定的頁面照舊可以。閒置 30 分鐘、電腦鎖定、刪除家人對所有頁面有效。新的 SSE 事件 `memory.presence_changed`（不含內容）通知所有頁面，Pi 收到後重讀狀態，顯示「正在用 X 的記憶」，可以說或點「不是我」，也可以選人 |
| Pi 頁面 | 看著說話時的臉部辨識、叫名字問候、喚醒時認聲音、通話中認聲音、記憶選人畫面都改經新通道。Pi 上的打字與語音聊天不經記憶，對話回覆標「未用記憶」，不顯示人物；即時語音那一行照核心回報的這通記憶狀態顯示（和 Mac 同一套規則）。家人辨識畫面與記憶管理在 Pi 上顯示「請在 Mac 的 Nous App 進行」 |
| 鏡頭 | 沒有新的打開方式：Mac 選單打開鏡頭後，Pi 頁面自己開 Pi 的鏡頭（依 `NOUS_CAMERA_LABEL` 找同款鏡頭）。Pi 的 Chromium 第一次會詢問，George 要按一次「允許」；套件仍不用自動允許的旗標 |
| Pi 效能 | 終端頁面的鏡頭分析間隔 160 毫秒（Mac 80 毫秒），臉部取樣每秒 2 次（Mac 4 次），先顧對話流暢度 |
| 打包 | Mac App 執行的是 `.mjs`，所以驗證程式放在 `shared/*.mjs`，`desktop/identity-ipc.mjs`、`memory-ipc.mjs` 轉出；App 打包改用 esbuild 把這兩個檔案打包進去 |

新增的介面文字都有英文（`src/messages.en.json`、`server/messages.en.json`）。

## 未驗證

- Pi 上實際認人、叫名字、喚醒時認聲音、通話中認聲音。
- Pi 的鏡頭名稱是否和 Mac 的 `NOUS_CAMERA_LABEL` 相符；Chromium 鏡頭權限詢問。
- Pi 4 跑 160 毫秒鏡頭分析與每秒 2 次臉部取樣時，對話是否仍流暢。
- 聲音特徵是用 Mac 麥克風登記的，Pi 麥克風認不認得出來。
- 打包後的 App（esbuild 打包的兩個檔案）。
- Mac 與 Pi 同時使用時，記憶候選與暫停是否照上面的規則分開（只有自動測試）。

## 已知限制

- 「本次人物」仍是全核心一份：Pi 選定 George 之後，Mac 的打字聊天也用 George 的記憶，而且 Mac 的鏡頭事件不會暫停它；要換人請在 Mac 選人或按「不是我」。閒置 30 分鐘與電腦鎖定仍會暫停。
- `X-Nous-Terminal` 與 `terminal` 只是頁面標記：本機任何程式都能帶任何名稱，所以它們只分開辨識與記憶候選，不擋存取。
- main.ts 的接線（哪個元件用哪個通道）仍以讀原始碼的測試檢查，沒有在真瀏覽器裡跑。

## Pi 實測步驟（待 George 執行）

1. Mac 開服務模式，從 Mac 選單打開鏡頭與常駐喚醒聆聽。
2. Pi 的 kiosk 第一次會詢問鏡頭，按「允許」。
3. 在 Pi 前看著畫面說話 10 次：記錄叫對名字、叫錯、沒叫的次數，以及「正在用 X 的記憶」是否出現。
4. 不看畫面說「Hello Nous」10 次：記錄以聲音叫名字的次數（只憑聲音叫名字仍受原本的校準規則限制）。
5. 通話中換另一位家人說話：記錄是否提出聲音候選。
6. 說「不是我」：確認改回全家共用。
7. 通話 10 分鐘，記錄斷續與延遲，和沒開鏡頭時比較；同時記 `top` 與溫度。
8. 結果填入 [Pi 測試報告](../experiments/RPI4_REMOTE_TERMINAL_REPORT.zh-TW.md)。
