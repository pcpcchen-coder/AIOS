# 「今天日期」改用本機時區驗證

日期：2026-11-05（Asia/Taipei）。分支：`claude/local-date-fix`（基於 main `80b5fb4`）。George 2026-11-05 要求修正，同時確認新增 Google 日曆行程不用確認。

**沒有在 Mac 上執行過。** 以下是 Linux 雲端的固定時刻測試。

## 1. 問題

給模型的「今天日期」原本用 `toISOString().slice(0, 10)`，那是 UTC 日期。台灣時間 00:00–08:00 之間會變成前一天，模型換算「明天」「下週三」時就差一天；查日曆或排行程時特別明顯。

## 2. 修正

新增 `server/local-date.ts`：「今天」一律用本機系統的時區。Nous 核心跑在家裡的 Mac 上，系統時區就是使用者所在的時區。說明文字的那一行改成「今天日期：2026-11-05（星期四，Asia/Taipei）。」，多了星期幾與時區，模型換算「下週三」比較準。

改到的地方：

| 位置 | 用途 |
|---|---|
| `server/realtime.ts` | API key 即時語音、ChatGPT 方案即時語音的說明 |
| `server/live-tool-caller.ts` | ChatGPT 方案路徑替語音模型執行工具的說明 |
| `server/chat.ts` | 一般文字對話的系統說明 |
| `server/prompts.ts` | 背景任務規劃與每一步的預設日期（只有日期，格式不變） |

`tests/apikey-route.test.ts` 有一個「沒有記憶時，請求和 658b97a 快照逐位元組相同」的測試，比對前會把日期那一行換成 `<DATE>`。這次只更新它的正規化規則，讓它認得新的日期格式；快照本身沒有改，其他內容仍然逐位元組相同。

## 3. 測試

新測試檔 `tests/local-date.test.ts`，4 項：

- 2026-11-04T17:00Z（台北 11-05 凌晨 1 點）：舊寫法是 11-04，新寫法是 2026-11-05（星期四）。
- 跨年（台北 2027-01-01）、比 UTC 慢的時區（洛杉磯仍是 11-07 星期六）、UTC 本身。
- 系統時區是合法的 IANA 名稱。
- 兩條即時語音路徑（中英文）、ChatGPT 方案路徑、一般文字對話的說明都含有同一行本機日期，而且各只有一行；背景任務的規劃與步驟用本機日期。

指令與結果（2026-11-05，Linux 雲端、Node.js 22）：

- `npm run typecheck`：通過。
- `npx vitest run`：137 個檔案，2,498 項通過、5 項跳過。

## 4. Google 日曆行程不用確認

George 2026-11-05 確認：新增行程不出確認卡（`reversible_write`；只加在自己的日曆、不邀請人、刪得掉）。程式行為原本就是這樣，這次只在程式註解與 [CAL-1 驗證](cal-1-google-calendar-2026-11-05.md) 記下這個決定。
