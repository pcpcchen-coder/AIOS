# LGTV-1 用語音控制客廳 LG 電視：連線、配對、基本控制與狀態

日期：2026-11-07（Asia/Taipei）。分支：`claude/lgtv-1`。George 2026-11-07 要求：讓 Nous 依需求控制 LG 電視、播放想看的節目。這一批（LGTV-1）做連線、配對、開關機、音量、靜音、切輸入、開 App、播放控制與狀態回讀；**播放指定節目（YouTube 影片、搜尋、Netflix 深層連結）留到 LGTV-2**。

**沒有在 Mac 或真實電視上執行過。** 雲端沒有電視：測試用 `ws` 起一台「假的 webOS 電視」（fixture，只模擬 SSAP 訊息）和假的網路喚醒。實機狀況引用 LGTVG3 在 OLED65G3PSA 上的紀錄，不是本批的結果。

## 2. 設計

- **整合層 Adapter**：`lg_tv`（服務段 `tv`）。兩條即時語音路徑（API key 與 ChatGPT 方案）拿到同一份 `app__tv__*` 工具，由核心執行，沒有另一套工具介面。
- **核心直接連電視**：Mac 上的 Nous 核心用 SSAP 連電視（新依賴 `ws@8.22.0`，MIT）。每次工具呼叫開一條連線，做完就關，不常駐、不訂閱。Nous 不開任何新的埠，電視控制不經頁面，也不給區網外。
- **設定**：`NOUS_LGTV_HOST` 只接受私有網段 IPv4（10/8、172.16/12、192.168/16），格式錯就無法啟動。模型不能指定 IP、MAC、金鑰或 SSAP 位址，只能從固定動作裡選。
- **配對金鑰**：只存在 `<configDir>/lgtv.json`（預設 `~/.config/nous/lgtv.json`，權限 0600），由 `npm run tv:pair` 寫入，核心只讀。金鑰不進 log、不交給頁面或模型，也不在 repo 裡。配對的 IP 和 `NOUS_LGTV_HOST` 不同時，當作沒有配對。
- **MAC**：配對時先查 Mac 的 ARP 表，找到電視目前用的那張網卡就只記那張；找不到就把電視回報的有線與 Wi‑Fi 兩張都記下，喚醒時兩張都送。`NOUS_LGTV_MAC` 可以覆蓋。
- **確認**：開關機、音量等都是可逆的動作，不在產品紅線列的外部副作用內，所以不出確認卡。開 App 或切輸入時電視沒開，會先開機（2026-10-31「便利優先」）。這兩點要 George 確認，見第 10 節。
- **和開燈一樣直接說**（George 2026-11-07）：兩條即時語音路徑的說話規則加了一段電視規則（有 `app__tv__` 工具時才出現）：沒指名房間的「電視」就是客廳這台，用 `app__tv__*`；「電視大聲一點」「電視靜音」用 `app__tv__volume`／`app__tv__mute`，不再交給中控。
- **中控那條的「電視」取消**（George 2026-11-07）：啟用 `lg_tv`（有 `NOUS_LGTV_HOST`）時，`home_control` 對「電視」「客廳電視」「LG 電視」，以及客廳裡名稱以電視結尾的中控設備一律回 `refused`（`unsupported`，提示改用電視工具），不送紅外線按鍵。其他房間的電視（例如臥室電視）、其他家電與 `home_status` 查詢不受影響。`home_control` 的工具說明沒有改（逐位元組測試鎖住），由說話規則與中控端拒絕導向新方法。
- **Spotify**：Spotify 開發者政策 III.3 禁止用語音控制 Spotify，AIOS 的 SP-2 也是 BLOCKED。在 George 決定前，`launch_app` 拒絕開電視上的 Spotify，不送出指令；找不到 App 時回的清單也不列 Spotify。

## 3. 支援的指令

## 4. 狀態對照（誠實狀態）

| 情況 | status | 說明 |
|---|---|---|
| 指令送出且回讀相符 | `confirmed` | 只有這種可以說「好了」 |
| 指令送出，讀不到或不符（例如接聲霸時音量讀不到、開 App 後前景沒變、喚醒後 25 秒沒上線、播放控制） | `unconfirmed` | 請使用者看一下 |
| 指令送出後連線中斷或電視沒回覆；Dispatcher 時限到 | `unknown` | 不能說成功或失敗 |
| 寫入已被電視接受後才出錯（例如音量調到第 3 格被拒、喚醒後電視不認得金鑰） | `unconfirmed` | 不說「沒有送出」或「失敗」 |
| 開 App／切輸入時開機沒有確認 | `unconfirmed` | 說「已送出開機，但還沒有開 App」，App 沒有送出 |
| 連不上電視（沒有送出）；電視明確拒絕；沒有這個 App 或輸入源；電視待機時調音量；沒有 MAC 無法喚醒；喚醒封包送不出去 | `failed` | 照實說原因 |
| 還沒配對、Spotify、參數不對 | `refused` | 沒有送出 |
| 關機時連不上電視 | `failed`（`sent: false`） | 可能已經關了，但沒有送出關機指令 |
| 狀態查詢連不上 | `confirmed`（`reachable: false`） | 照實說「連不上，可能關機待機或不在網路上」，不推定是關機 |

設定頁「App 整合」顯示「客廳 LG 電視」：連得上是「可用：已連線」；連不上是「狀態不明：連不上（電視可能關機待機或不在網路上）」，並附註「待機時連不上是正常的」；沒有配對時顯示「還沒配對」。整合層的健康原因代碼為此新增 `unreachable` 與 `not_paired`。

## 5. 測試（fixture，不是實機）

新增測試檔 `tests/integration-lg-tv.test.ts`，共 30 項；`tests/home-bridge.test.ts` 加 1 項：

- **SSAP 用戶端**：配對提示時等「允許」並取得金鑰；一般呼叫遇到提示立刻停止，不等使用者；金鑰錯誤要重新配對；連不上、電視拒絕、送出後斷線分屬三種錯誤；第一個網址連不上時改試第二個（對應 wss:3001 → ws:3000）。
- **配對檔、MAC、名稱**：配對檔權限 0600；看不懂的檔案當作沒有配對；可以刪除。MAC 正規化，magic packet 為 102 位元組。App 別名與相似度比對，沒有安裝的 App 不開。輸入源可用 HDMI 2、2 或「Apple TV」指定。
- **Adapter**：
  - 沒有配對或 IP 不同時不連電視。
  - 狀態查詢在開機、待機、連不上三種情況都正確。
  - 開機：已開著、Quick Start+ 待機、網路喚醒後電視上線（假電視收到封包才啟動），這三種是 `confirmed`；沒有 MAC 是 `failed`；喚醒後沒上線是 `unconfirmed`，等待期間有補送封包。
  - MAC 覆蓋，以及兩張網卡都送。
  - 關機：電視斷線是 `confirmed`；電視不理是 `unconfirmed`；連不上時是 `failed`（`sent: false`）；已經待機時不送關機。
  - 音量的設定、調高、調低都有回讀；聲霸讀不到時是 `unconfirmed`；待機或連不上時不送。
  - 靜音：成功、電視拒絕、送出後斷線（`unknown`）三種情況。
  - 切輸入源：成功、沒有這個輸入源、前景沒變三種情況。
  - 開 App：中文別名、沒有安裝、Spotify 拒絕且沒有送出、前景沒變。
  - 電視待機時開 App，會先開機再開 App。
  - 播放控制只會是 `unconfirmed`。
  - 健康狀態有三種。
  - 結果與工具清單都不含金鑰。
- **設定與整合層**：`NOUS_LGTV_HOST` 拒絕公網 IP、網域名稱與錯誤位址；MAC 與廣播位址格式檢查；沒有 IP 時不註冊並記 log；兩條路徑的工具名稱與參數相同；模型多塞 `host` 參數時 Schema 拒絕、不執行。
- **獨立審查後補的**：握手時 socket 出錯（壞封包）只讓連線失敗、不會讓核心崩潰；同一封包多則訊息與晚到回覆照 id 取；音量調到一半被拒是 `unconfirmed`；喚醒後配對錯誤是 `unconfirmed`；喚醒封包送不出去是 `failed`；開 App 時開機沒確認會說還沒開 App；`010.0.0.1` 這種前導 0 的位址被拒（會被解析成公網的 8.0.0.1）。

## 7. 在家裡的 Mac 實測步驟（尚未執行）

1. **電視設定**：設定 → 一般 → 裝置 → 電視管理（或「外部裝置」）：開啟「透過 Wi‑Fi 開機」與「LG Connect Apps」。在路由器幫電視保留固定 IP。
2. **更新並安裝**：拉取 main 之後，在 `prototype/ambient-shell` 執行 `npm ci`（會新增 `ws`）。
3. **配對**：電視開著，執行 `npm run tv:pair -- --host <電視 IP>`，看到提示後用遙控器按「允許」。成功時會印出存放位置與 MAC（不印出金鑰）。確認 `ls -l ~/.config/nous/lgtv.json` 是 `-rw-------`。如果自訂了 `NOUS_CONFIG_DIR`，要用同一份 `.env`：`npm run tv:pair -- --env <你的 .env>`。
4. **設定 Nous**：在 `.env` 加上 `NOUS_LGTV_HOST=<電視 IP>`，並在 `NOUS_AIL_SERVICES` 加上 `lg_tv`（`NOUS_AIL=on`），然後重新啟動 Nous。
5. **看狀態**：設定頁「App 整合」應顯示「客廳 LG 電視：可用」。
6. **用語音**（兩條即時語音路徑各試一次）：
   - 「電視現在開著嗎？在看什麼？」：回答要符合電視畫面與音量。
   - 「把電視關掉」：電視關機，Nous 說關了。等 1 分鐘、1 小時、隔夜後各說一次「開電視」，記錄是否喚醒成功、花幾秒（LGTVG3 還沒測過 Wake-on-LAN）。
   - 「音量調到 15」「大聲一點」「靜音」「取消靜音」：要對得上電視顯示。接聲霸時，看是否回答「請聽一下」。
   - 「切到 HDMI 2」「開 YouTube」「開網飛」「開 Disney+」：電視切過去；沒裝的 App 要說沒有安裝。
   - 「暫停」「繼續播放」：只能說「已送出，請看一下電視」。
   - 「開 Spotify」：要說沒有授權、沒有送出。
   - 確認中控不再控制電視：說「電視開關」時，中控紀錄不應該出現紅外線按鍵；臥室電視（如果有）仍由中控控制。
7. **失敗路徑**：拔掉電視網路線（或關掉 Wi‑Fi）後問狀態，要說連不上，不能說關機。
8. **確認沒有外洩**：Nous 的 log 只有「整合層」的工具與狀態代碼，沒有金鑰或 IP 以外的設定。
9. **回報**：記錄每一項結果，尤其是開機秒數、哪個 MAC 有效，以及音量讀回是否相符。

## 8. 回退

- **停用**（同時恢復中控控制電視）：從 `NOUS_AIL_SERVICES` 拿掉 `lg_tv`，或刪掉 `NOUS_LGTV_HOST`，然後重新啟動 Nous，就不會註冊任何 `app.tv.*` 工具。`NOUS_AIL=off` 會關掉整個整合層。
- **移除金鑰**：`npm run tv:pair -- --forget`（刪除 `<configDir>/lgtv.json`）。電視端在「設定 → 一般 → 裝置 → 外部裝置／電視管理」的已連線裝置可以移除配對；選單名稱依韌體而異，需在實機確認。
- **程式回退**：revert 這個 PR。新增的健康原因代碼只有這個 Adapter 使用。

## 9. 限制與未完成

- 沒有在 Mac 或真實電視上驗證，第 7 節還沒做。
- 播放指定節目（YouTube 影片 ID 或搜尋、Netflix 深層連結、YouTube「誰在觀看」畫面）留到 LGTV-2。LGTVG3 已在實機驗證 YouTube `contentTarget` 可以直接播放。
- 搜尋來源的條款（2026-11-07 查核，詳細見 LGTV-2）：
  - YouTube Data API 的 `search.list` 現在有獨立配額，每天約 100 次。
  - 用 yt-dlp 或解析 youtube.com 搜尋頁抓結果，違反 YouTube 服務條款（禁止 scraper）。
  - Netflix、Disney+、Prime Video 沒有公開的深層連結，只有社群做法或合作夥伴保密文件。
  - DIAL 由 Netflix 與 YouTube 推出，但 YouTube 的 `v=` 參數只有社群文件。
- 每次呼叫重新連線，大約多 0.5–1 秒，可能影響回應速度，實機才能量到。
- 電視「螢幕關閉」（只有聲音）時，狀態回 `screen_off`，開機工具視為已經開著。
- 沒有接腦區動畫：API key 路徑的整合工具目前只顯示字幕，和其他 `app__` 工具相同。
