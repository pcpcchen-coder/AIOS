# Nous 原型：漂浮電子腦 × ChatGPT 對話 × 按需任務

> 以電子腦呈現語音對話。登入自己的 ChatGPT 帳號後啟動收音，可插話，也可打字接著聊。需要較長工作時，AI 可沿用原型的背景任務流程。

## 啟動

需要 Node.js 22.12 以上。第一次安裝、Windows 指令與常見問題見 **[INSTALL.md](./INSTALL.md)**。

```bash
cd prototype/ambient-shell
npm ci
npm start                 # 建置前端並啟動本機核心
```

開啟 <http://localhost:8787>。伺服器只綁 `127.0.0.1`。

開發時可分兩個終端機：`npm run dev:server`（核心，8787）與 `npm run dev:web`（Vite，5173，`/api` 轉給核心）。

點電子腦或「開始語音對話」，依提示登入 ChatGPT，再次按下語音入口並同意雲端語音辨識。登入不會自動開啟麥克風。ChatGPT 帳號需要取得既有 Sign in with ChatGPT 預覽流程的授權；本次未完成真實帳號的登入或推論驗證，不能保證每個方案皆可使用。不要把 ChatGPT 密碼或憑證填入 `.env`。

## 怎麼用

| 你做的事 | 它的反應 |
|---|---|
| 點電子腦或「開始語音對話」 | 需要時先登入 ChatGPT，再由你啟動收音；電子腦呈現聆聽、等待回覆與播報狀態 |
| 按空白鍵或直接打字，Enter 送出 | 接續同一段對話。麥克風不可用時仍可看文字回覆，不會把一般問答另建任務 |
| 說話插入、或播報時按 Esc | 停止當前生成及播報，回到聆聽；接著問的新問題會使用正確的對話順序 |
| 按「結束對話」按鈕、說／打「收起」，或非播報時按 Esc | 停止前景收音及回覆，收起畫面並結束語音；既有背景任務繼續執行。說「結束對話」不是本機指令（會交給 AI），見下方指令表 |
| 「進度如何」「做到哪了」 | 叫出所有任務的進度：狀態、`完成步數 / 總步數 · 百分比`、每一步的狀態與耗時、串流中已產生的字數 |
| 「看結果」「剛才那份」 | 叫出最新完成的成果 |
| 「停止任務」 | 只有一個在跑就直接停止；多個時列出讓你選 |
| 麥克風按鈕（Chrome／Edge） | 按下說話。第一次會先說明：瀏覽器會把音訊送到其雲端辨識，同意後才啟用 |
| 說／打「開啟語音模式」，或按輸入框的聲波按鈕 | **語音對話模式**（類似 ChatGPT 語音模式）：直接和 AI 對談，回覆邊產生邊逐句念出；**它說話時你可以直接插話**，它會停下來聽你說。需要較長時間的工作（寫報告、整理資料）由 AI 自行交辦成背景任務，進度照常顯示。「進度如何」「停止任務」「收起」等指令仍由本機直接處理（即時語音中用說的則交給 AI，見下方指令表）。說「關閉語音模式」、點右上角指示，或閒置太久（預設 1 分 30 秒，可調）就關閉 |

只有「短句且符合固定語彙」才被當成控制指令（`src/intent.ts`）。例如「幫我寫一份專案進度報告」會交給 AI 理解，不會被誤判成查進度。電子腦對話使用瀏覽器 STT、ChatGPT 文字串流及瀏覽器 TTS。這條路徑的延遲與聲音由瀏覽器辨識服務、模型及電腦語音共同決定。

最新一輪對話可保留閱讀，直到收起或另開設定、進度等視圖。歷史只存在目前頁面的記憶體中，切換引擎、帳號或登出會清除。重新載入頁面也會清除。

### 語音閒置秒數

| 設定 | 預設 | 範圍 | 什麼時候不計時 |
| --- | --- | --- | --- |
| 語音模式閒置多久自動關閉 | 1 分 30 秒 | 30–600 秒，每格 10 | 等 AI 回覆與念回覆時 |
| 即時語音閒置多久自動結束 | 2 分鐘 | 30–600 秒，每格 10 | 回覆、查資料、執行工具、等確認時（即時語音依用量計費） |

在「設定」畫面用 −／+ 調整，macOS App 也可以在選單列「秒數與倍率設定」選。改了立即生效：開著的語音從改的那一刻重新計時；關著的下次開啟才用。保存在 `~/.config/nous/voice.json`（只存改過的項目，`POST /api/settings/voice`），規則與 `camera.json` 相同：不合法的項目逐項忽略並記 log，檔案讀不懂時用預設值。範圍、選項與標籤只寫在 `shared/voice-prefs.ts`，選單列的選項由本機核心推導（`GET /api/settings` 的 `seconds`；欄位名沿用舊名，現在也含倍率列，以 `kind` 區分）。

#### 容易誤會

每一句的比對結果都由測試確認。

| 這句話 | 實際上會怎樣 |
|---|---|
| 「結束對話」 | 不是本機指令。打字、按麥克風或語音模式中會當成一句話交給 AI；即時語音中由 AI 判斷要不要結束（不保證）。要確定結束：點右上角的語音指示、按畫面上的「結束對話」按鈕，或打「關閉語音模式」（語音模式中用說的也可以） |
| 「開始語音對話」 | 這是按鈕與選單的名稱，說出或打出來不是指令（會交給 AI）。請說「開啟語音模式」、按畫面上的按鈕，或在 App 按 ⌥⌘V |
| 「再見」 | 本機不認。只有即時語音中 AI 可能因此結束對話（由模型判斷）；其他時候會當成一句話交給 AI |
| 「停」 | 語音模式中 Nous 正在念時會打斷播報；這個字之後仍會當成一句話交給 AI，不會停止任務。要停止任務請說「停止任務」 |
| 「stop」 | 語音模式中先打斷播報，接著當成「停止任務」：有進行中的任務會被停止 |
| 「取消」 | 打字、按麥克風或語音模式中是「停止任務」。即時語音確認卡開著時，用說的才是單純拒絕；用打的會先當成停止任務，停止任務會換上進度或通知畫面，而確認卡被換掉也算拒絕：確認卡被拒絕，有進行中的任務時也會被停止 |
| 「關閉手掌停止」「停用停止手勢」「打開手掌停止」「啟用停止手勢」 | 即時語音確認卡開著時說這幾句，除了改手掌停止的設定，也會因為含「停止」而拒絕確認卡。用打的不會（鏡頭規則先處理，不再檢查確認語句） |
| 「關掉鏡頭」 | 即時語音中說鏡頭指令：本機照做，這句話也仍會送到 AI，AI 可能另外回應 |
| 「收起」 | 收起畫面的同時也會結束語音模式或即時語音；進行中的任務不會停止（停止任務才會） |
| 「進度如何」「設定」「看結果」「改用 Claude」「停止任務」 | 即時語音確認卡開著時打這些字：會換上進度、設定、成果或通知畫面，確認卡被換掉就算拒絕，外部動作不執行（即使這句話本身不是確認或取消的說法）。要同意請打或說「確認執行」等確認語句 |
| 「停止任務」「進度如何」「收起」 | 即時語音中用說的，這些都不在本機處理，會交給 AI：問進度 AI 會查真實狀態回答；AI 沒有停止任務或收起畫面的工具。要停止任務，請打「停止任務」或按進度畫面上的停止按鈕；要收起，請打「收起」、按 Esc 或點畫面上的按鈕。Esc 只會打斷說話或收起畫面，不會停止任務。確認卡開著時，含「停止」的話會拒絕確認卡 |
| 「確認執行停止播放」 | 確認卡開著時，這句話因為含「停止」而算取消，家電指令不會執行。要同意只說「確認執行」，不要把動作接在後面 |
| 「好」 | 確認卡開著時只說「好」不算同意，也不算取消：指令不會送出，確認卡繼續等你說「確認執行」或「取消」，60 秒後自動取消 |
| 「冷氣調 26 度」 | 不是本機指令，會交給 AI。AIFA 冷氣：先讀控制器記得的設定再送出 26 度，讀不到的項目用預設值並說出來；冷氣不會回報，所以只會說「已送出，請確認」，不會說調好了，冷氣關著時也不代表會開機（要開請說「開冷氣」）。紅外線遙控的冷氣只能按它的遙控鍵；色溫（2500–9000 K）只用在燈 |
| 「客廳的燈全部關掉」 | 一次只控制一台：說整個房間或「全部」時，AI 會問你是哪一台，不會一次關掉整個房間 |
| 「交通狀況如何」 | 14 個字以內、句中有「進度」「狀態」「狀況」「好了沒」「做到哪」等詞（又沒有寫、整理、規劃等交辦動詞）就算查進度：例如「交通狀況如何」會打開進度，不會交給 AI。想問 AI 請把句子說完整，或用即時語音 |
| 「比賽結果」 | 同樣地，短句中有「結果」「成果」「給我看」「拿出來」等詞就算看成果：例如「比賽結果」會打開最近的成果，不會交給 AI |

## 腦區如何連動

電子腦包含六個功能區。亮度、區名與光脈衝反映應用事件或主題分類，並標示來源。

| 腦區 | 對應內容與事件 |
| --- | --- |
| 語言區 | 閱讀、撰寫、翻譯及實際語音播報。 |
| 數理區 | 計算、邏輯、資料分析與程式相關主題或任務步驟。 |
| 藝術區 | 設計、故事、美感與創作主題或任務步驟。 |
| 聽覺區 | 瀏覽器實際收音，以及明確標示的音訊相關主題。 |
| 視覺區 | 影像、照片、觀察等主題分類；目前沒有攝影機或影像分析流程。 |
| 規劃區 | 任務規劃階段，以及拆解、安排等主題或任務步驟。 |

任務規劃器為每步標記 `domain`，Claude、ChatGPT 與模擬執行器都將它傳到任務事件。舊資料沒有領域標記時仍可載入。對話主題來自目前有效的一輪輸入；插話、失敗、完成或收起後，不會由舊回覆再點亮區域。背景任務仍可依真實執行狀態亮起。

開始語音模式不等於已開始收音。聽覺區的裝置活動要等瀏覽器回報音訊開始，結束、權限拒絕或關閉後清除。播報也等真正的播放開始事件才呈現。

這些區域是功能分類示意，不是模型內部神經活動或人類腦部量測。模擬任務會標明模擬來源。原分支的三區示意截圖保留在 `docs/screenshots/07-region-language.jpg` 至 `09-region-art.jpg`，六區結果以新的驗證紀錄為準。

## 進度怎麼算（不灌水）

- 每個任務先由 Claude **規劃步驟**；規劃完成前只顯示「規劃中：步驟數尚未確定」，不畫百分比。
- 規劃後：`百分比 = round(完成步數 / 總步數 × 100)`，總步數在 Claude 模式為「規劃步驟 1 + 計畫步驟 n + 彙整成果 1」。計算在 `shared/progress.ts`，案例在 `tests/progress.test.ts`。
- 「已產生 N 字」是串流實際收到的字元數；耗時是真實時鐘差。
- 電子腦的光脈衝只在真實事件發生時出現（交辦、步驟開始／完成、收到串流輸出、成功、失敗）；沒有事件就沒有脈衝。

## AI 引擎（可切換）

說或打「設定」叫出 AI 引擎設定；也可以直接說「改用 ChatGPT」「改用 Claude」「改用模擬模式」。選擇會保存，新交辦的任務用新引擎，已在跑的任務不受影響。

![設定：AI 引擎](./docs/screenshots/06-settings.jpg)

| 引擎 | 怎麼啟用 | 行為 |
|---|---|---|
| Claude | `.env` 設 `ANTHROPIC_API_KEY` | 依 API 用量計費。規劃 → 逐步串流執行 → 彙整 |
| ChatGPT | 設定畫面按 **Continue with ChatGPT**，在瀏覽器登入並同意 | 使用你的 **ChatGPT 方案額度**（不需要 API key）。走 OpenAI 官方的 [Sign in with ChatGPT](https://developers.openai.com/siwc) 開源／本機 app 流程，推論呼叫 `POST /v1/responses`（`store:false`、`stream:true`）。輸入列下方會顯示「使用 ChatGPT 方案 · 管理用量」 |
| 模擬 | 在設定中明確選擇，作為開發驗證 | 用計時器走固定步驟或回傳模擬對話，**未呼叫任何模型**；全程標示「模擬」。未登入時的 ChatGPT 對話入口會要求登入 |

Claude 與 ChatGPT 用同一套提示詞（`server/prompts.ts`）。兩者都沒有工具（不上網、不讀寫檔、不寄信），需要這些能力的部分會在成果中列為「能力缺口」。

**ChatGPT 登入細節**（依官方文件實作）：第一次以 `client_id=dynamic_agent_client` 動態註冊，之後沿用核發的 `client_id`；每台電腦一個 `ext_agent_host_id`（`urn:uuid:…`）；PKCE＋state＋nonce，回呼在 `http://127.0.0.1:1455/auth/callback`；驗證 ID token 簽章（JWKS）、issuer、audience、nonce，並確認取得 `chatgpt.tokens.use.direct` 才允許推論。access token 一小時到期，接近到期自動 refresh；登出時撤銷 refresh token。憑證存在 `~/.config/nous/chatgpt-credentials.json`（權限 0600），不放在 repo、不進瀏覽器儲存。用量上限、登入失效等錯誤會顯示「管理用量」或「開啟設定」。

模型不寫死：有設定 `NOUS_MODEL` 就用它；否則在第一個任務時經 Models API 取最新的 `NOUS_MODEL_FAMILY`（預設 `opus`）系列。預設開啟伺服器端 refusal fallback（beta `server-side-fallback-2026-07-01`），所選模型不支援時設 `NOUS_FALLBACKS=off`。

### 即時語音模式（兩條路徑：ChatGPT 方案或 OpenAI API key）

「開始語音對話」在有可用路徑時改用語音直接對語音，像 ChatGPT 語音模式。有兩條路徑，在 **設定 → 即時語音** 或 macOS App 選單列 **即時語音 → 路徑** 切換（不用改 `.env`、不用重新啟動；切換只影響下一次開始，進行中的對話維持原本的路徑）：

| 路徑 | 怎麼啟用 | 計費（畫面一律顯示） |
|---|---|---|
| **ChatGPT 方案（Codex 登入）** | 設定 → 即時語音 → 「用 ChatGPT 方案登入（Codex）」，在瀏覽器登入 | `ChatGPT 方案（Codex 額度）· gpt-live-1-codex`：語音、交辦時的推論與上網查詢都用方案的 Codex 額度，不需要 API key |
| **OpenAI API key** | `.env` 填 `OPENAI_API_KEY` | `OpenAI API key 計費 · gpt-realtime`：依用量計費（原本的路徑，行為不變） |

路徑偏好有三種：**自動**（預設；先用 ChatGPT 方案，不能用時改用 API key）、**ChatGPT 方案**（絕不改用 API key 計費）、**API key**。自動改用 API key **只在開始時**發生，而且會先說出並顯示「這次改用 OpenAI API key（依用量計費）：<原因>」；對話中途不會換路徑。兩條都不能用時照實說原因（例如「ChatGPT 方案路徑尚未登入；未設定 OPENAI_API_KEY」）。設定畫面、即時語音列、選單列與輸入列下方的引擎列都顯示目前的路徑與計費。`NOUS_REALTIME_ROUTE`（`auto`／`live`／`api_key`）只是預設值。

**ChatGPT 方案路徑（gpt-live-1-codex）** 照 OpenClaw 的做法，由本機核心自己登入 Codex 介面（不需要安裝 Codex CLI）：

- 登入：Nous 自己的 PKCE 登入，用 Codex 的公開 client（`app_EMoamEEZ73f0CkXaXp7hrann`），回呼在 `http://127.0.0.1:1455/auth/callback`；1455 被占用（例如 OpenClaw 或 Codex 正在登入）時改用 1457，兩個都被占用時改用裝置代碼登入（到 `auth.openai.com/codex/device` 輸入代碼）。憑證存在 `~/.config/nous/codex-credentials.json`（0600），和 Sign in with ChatGPT 的 `chatgpt-credentials.json` 分開。**Nous 從不讀、不更新、不寫 Codex CLI 的 `~/.codex`**，所以不會把你的 Codex CLI 或 OpenClaw 登出。token 接近到期時才更新（同一時間只更新一次）；沒有 ChatGPT 帳號 ID 的登入會被拒絕。
- 連線：核心代為 `POST chatgpt.com/backend-api/codex/realtime/calls`（JSON：SDP、說明文字、聲音、`delegation:{type:"client"}`；預設不送 model），再開 `wss://api.openai.com/v1/live/{callId}` 的控制連線（sideband）。權杖只在核心，不進瀏覽器、SSE、HTTP 回應或 log；CSP 仍只允許 `connect-src 'self'`。
- 工具：`gpt-live-1-codex` 沒有函式工具，需要做事時會「交辦」。核心用同一個 Codex 登入呼叫 Codex Responses，給它和 API key 路徑**同一份工具表與規則**，每個工具再交給**頁面上同一個執行器**（`src/realtime-tools.ts`）執行。所以交辦工作、進度、成果畫面、字幕、確認卡、電子腦光脈衝與完成時的語音通知在兩條路徑上是同一段程式。上網查詢改走 Codex 的 hosted `web_search`（Codex 額度）；背景任務仍由目前選擇的 AI 引擎執行。
- 誠實規則：「聆聽中」要麥克風軌道、peer 已連線、收到 `session.started`；「回覆中」看遠端音量。家電指令照中控回讀說話；有副作用的工具（家電、交辦）沒有在時限內回報時只說「結果不明，請確認」，不說失敗。確認卡只由按鈕或你說出的「確認執行／取消」決定，Codex 那邊不能替你確認。控制連線斷線、登入失效或時間到時直接結束並說出原因，不改路徑。
- 這條路徑沒有：遠端 MCP（請切換到 API key 路徑）、取消回覆的指令（Esc 只把這段回覆靜音）。一個核心同時只能有一個 ChatGPT 方案即時語音；開始它的頁面重新整理或關閉時立刻結束，重新整理後可以馬上再開始。
- 聲音：`arbor、breeze、cove（預設）、ember、juniper、maple、sol、spruce、vale`，在設定或選單列切換（`NOUS_LIVE_VOICE` 是預設值）。`NOUS_LIVE_MODEL`（顯示用預設 `gpt-live-1-codex`，設定了才送出）、`NOUS_LIVE_AGENT_MODEL`（交辦時的 Codex 模型；未設定時查 Codex 模型清單）。
- 這是 OpenAI 未公開文件的介面（OpenClaw 也用這條）。實作完成，但**還沒有在真實帳號上驗證**：所有測試都是假的 chatgpt.com、假的 sideband 與假的頁面；George 的家中測試步驟與門檻見 [`docs/validation/live-voice-2026-10-23.md`](../../docs/validation/live-voice-2026-10-23.md)。

**OpenAI API key 路徑（gpt-realtime）** 和之前一樣（預設 `gpt-realtime`，可用 `NOUS_REALTIME_MODEL`、`NOUS_REALTIME_VOICE` 調整）：

- 瀏覽器用 WebRTC 把麥克風串流到 OpenAI，由 `semantic_vad` 判斷說完了沒；使用者一開口，OpenAI 會截斷正在播放的回覆（插話）。
- SDP 交換經本機核心 `POST /api/realtime/call`：核心用 API key 換一把 120 秒的 client secret，再代為送出 SDP。API key 不會送到瀏覽器，頁面 CSP 仍只允許 `connect-src 'self'`。
- 模型的工具：`web_search`（上網查即時資料：天氣、新聞、價格等；由本機核心 `POST /api/realtime/web-search` 用同一把 key 呼叫 Responses API 的 `web_search`，預設模型 `gpt-5.5`、位置台灣，可用 `NOUS_SEARCH_*` 調整，來源顯示在字幕）、`delegate_task`（交辦需要較長時間的工作，**由目前選擇的引擎執行**，例如 ChatGPT 方案；查詢類問題不交辦）、`get_tasks`（查真實進度）、`end_conversation`（道別後結束）。任務完成時會以「（系統通知）」請模型用一句話轉告；多則通知會排隊，一次只要求一個回應。
- 遠端 MCP：在 `NOUS_REALTIME_MCP` 填 JSON 陣列，伺服器會直接掛到 Realtime 工作階段，由 OpenAI 端連線呼叫。`require_approval` 預設 `always`：需要核准的動作（寄出、發布等）會顯示琥珀色確認卡，列出服務、工具與參數，並請模型用一句話說明；使用者**說「確認執行」**才執行，說「取消」、60 秒沒回應、或收起確認卡都不執行。判斷由本機的固定語句規則（`shared/approval.ts`）做，不由模型轉述同意；只說「好」不算，句中有取消類詞語一律視為取消。不需要按任何東西。
- 背景任務與文字對話：引擎支援時也帶上網搜尋（ChatGPT：Responses `web_search`；Claude：`NOUS_CLAUDE_WEB_SEARCH`，預設 `web_search_20250305`）。被拒時自動改送不帶工具的請求，並把「未經查證」寫進能力缺口。`NOUS_TASK_WEB_SEARCH=off` 可關閉。
- 打字輸入也會進同一段即時對話；有畫面開著時 Esc 只關畫面，沒說話一段時間（預設 2 分鐘，可調，見「語音閒置秒數」）自動結束以免持續計費。
- 注意兩種 ChatGPT 登入不同：上面 AI 引擎的 **Sign in with ChatGPT**（`chatgpt-credentials.json`）用在背景任務與文字對話，它的權杖仍然不能用在即時語音（實測推論 `server_error`）；即時語音的方案額度要用另外的 **Codex 登入**（`codex-credentials.json`）。

### 雙目鏡頭（docs/11）

`.env` 設 `NOUS_CAMERA=on`，並先執行一次 `npm run vision:setup`（把 MediaPipe wasm 複製到 `public/vision/`，下載 Pose 與手勢模型，約 30 MB），之後 `npm start` 會自動開啟鏡頭，不需要按任何東西：

| 用法 | 怎麼判斷 | 會做什麼 |
| --- | --- | --- |
| 在場與距離 | 左右眼的鼻子與雙肩三角化，取深度中位數；連續 0.5 秒才算在場，60 秒沒看到才算離開 | 依距離縮放內容面板、字幕與頂端縮略圖（× D ÷ 2.0 m，限 0.75–1.5 倍）；待機的電子腦反過來靠近時放大（見下）；人離開時收起畫面、結束即時語音、待確認的外部動作一律不執行 |
| 面向螢幕 | 鼻子相對雙耳中點的偏移（頭部方向，不是眼睛視線），0.3 秒遲滯 | 電子腦微亮；在場且從開始面向算起 1.5 秒（可在設定調整）就自動開始即時語音（看著說話，需先同意過一次即時語音） |
| 停止手勢 | 張開手掌（手勢模型）且手腕高於肩膀，持續 0.3 秒；兩次至少相隔 2 秒 | 只停止播報，不取消任務、不送任何指令（可在設定關閉） |
| 手臂指向 | 肩膀與手腕的 3D 點連線與螢幕平面的交點，分左／中／右；同一區穩定 0.45 秒才算 | 該區的可選項目亮框，並告訴模型「使用者指著哪一項」；只是選定，不展開、不執行 |

### 武陵居家電查詢與控制（docs/12 H0、H1、H1b）

`.env` 設 `SMARTHOME_URL` 與 `SMARTHOME_TOKEN` 後，即時語音多兩個工具：`home_status` 回答「客廳現在幾度」「書房二氧化碳多少」「客廳主燈在不在線」；`home_control` 執行「客廳主燈關掉」「書桌燈調到 60%」「色溫調到 3000K」「冷氣調 26 度」「電視大聲一點」。

- 本機核心的 HomeBridge（`server/home-bridge.ts`）帶權杖呼叫中控：查詢用 `GET /api/v1/home` 與 `GET /api/v1/integrations/aifa`（AIFA 冷氣只在這份清單裡），控制用 `POST /api/v1/devices/{id}/commands`；AIFA 冷氣用 `…/integrations/aifa/devices/{hub}/children/{child}/power`、`/status`、`/climate`，紅外線家電用 `POST /api/v1/devices/{id}/infrared-commands`。瀏覽器經 `POST /api/home/status`、`/api/home/control`、`/api/home/confirm` 取得結果。權杖不進瀏覽器，也不進 OpenAI 的工作階段設定；OpenAI 只看到結果。
- 名稱用確定性比對：全家 → 設備名稱或別名完全相同 → 房間 → 房間加設備名稱 → 名稱包含。多個候選時回傳 `ambiguous` 讓模型問是哪一個，不自己挑。「客廳溫度」這種說法會拆成房間與讀值。中控提供 `GET /resolve` 後改用中控的比對（H2）。
- 讀值照中控回報：缺值是 `null`，字幕與語音說「沒有讀值」，不說 0；中控標為快照或過期的資料會連同時間一起說。時間與「幾分鐘前」用中控的 `server_time` 計算。
- **控制一次一台**：說房間或「全部」會先問是哪一台（房間指令是 H3）。可用指令：開關、亮度、燈的色溫（2500–9000 K）、顏色、音量、靜音、播放／暫停／停止、窗簾。
- **AIFA 冷氣（H1b）**：開關、設定溫度（17–30 度）、模式（自動、冷氣、除濕；沒有暖氣與送風）、風量、擺風。設定溫度前先讀控制器記得的設定，讀不到的項目用預設值並說出來；冷氣關著時調溫度不代表會開機。「開冷氣 26 度」會分成開關與設定兩個指令。AIFA 清單超過 24 小時時自動請中控重新讀取一次。
- **紅外線家電（H1b）**：電視、電風扇等一次按一個遙控鍵（電源、音量、頻道、靜音、風速、擺頭，或說按鍵名稱）。Nous 依中控同步到的按鍵名稱找鍵，沒有這個鍵就照實說並列出有的鍵；電源鍵與靜音鍵是切換鍵，只說「按了電源鍵／靜音鍵」，不說開了、關了或靜音了。按鍵沒同步時請到中控的紅外線控制器按「同步」，Nous 不會自己同步。紅外線遙控的冷氣也只能按鍵。不是 AIFA 的冷氣（Tuya、Home Assistant）與無線按鈕還不能用語音控制。
- **冷氣與紅外線沒有回讀**：結果永遠不是「已確認」，字幕是「⏳ … 已送出，請確認」，Nous 請你看一下；「控制器回報」只是控制器記得的設定，不是冷氣的實際狀態。每句話最多花 60 秒。
- **結果照中控回讀**：`confirmed` 才說好了；`unconfirmed`（例如易微聯插座、或設備回讀逾時）說「已送出、未確認」，請你看一下；中控兩次都沒回覆時說「不確定有沒有執行」；失敗照中控的原因說。每個指令帶 `Idempotency-Key`，逾時用同一把 key 重送一次，中控不會執行兩次。設備狀態過期時自動請中控重新讀取一次再送；仍不行就說沒有送出。每分鐘最多 6 個控制指令。
- 字幕顯示一行錨點，例如「客廳 溫濕度計：溫度 26.5 °C（14:29）」「✓ 客廳主燈 關閉：已確認」「⏳ 插座 開啟：已送出、未確認」。docs/12 §3 的大數字與大圖示畫面尚未做。
- 家電一律直接執行（George 的決定）。需要確認的家電會用同一張語音確認卡（說「確認執行」才送），但要等中控提供每台設備的語音設定（H2）；H1 只在測試裡觸發。

已驗證：假中控測試，以及真實中控程式（SmartHomeAI，示例配置；示例設備沒有真實位址，所以只走得到「狀態未更新」「未完成接入」「不支援」「失敗」這幾種結果；H1b 用寫進中控的 fixture 清單與按鍵，沒有 AIFA 帳號與 Tuya 認證，只走得到「失敗」「沒有送出」與冷卻重送），見 [H0 驗證紀錄](../../docs/validation/smarthome-h0-2026-10-21.md)、[H1 驗證紀錄](../../docs/validation/smarthome-h1-2026-10-22.md)、[H1b 驗證紀錄](../../docs/validation/smarthome-h1b-2026-10-22.md)。George 已在家裡用即時語音開關燈（口頭回報）；冷氣與紅外線家電尚未在家裡實測。

任務與成果存在 `data/`（已排除於 git），重啟後可喚回；重啟時尚未完成的任務會標為「中斷」失敗，不假裝仍在執行。

## 已知限制

- 未用真實 API key 或真實 ChatGPT 帳號跑過完整成功流程（開發環境沒有帳號）。已驗證：Claude 與 OpenAI 真實 API 的 401 失敗路徑；ChatGPT 登入流程以本機簽發的 ID token 和假端點做自動化測試；`auth.openai.com` 授權頁在開發環境被 Cloudflare 機器人驗證擋住，未能實際走完登入。
- ChatGPT 方案用量目前是 OpenAI 的預覽功能，Plus 方案的五小時用量上限與其他 app 共用。
- 語音用瀏覽器內建的 Web Speech API（雲端辨識）與 speechSynthesis（電腦語音），沒有本地喚醒詞；路線是「語音轉文字 → AI 對話 → 文字轉語音」三段串接，延遲比 ChatGPT 的語音對語音模型長。
- 插話靠「比對聽到的字和正在念的字」分辨回音與使用者：大多數字都在念的內容裡就當回音，出現新的字或「停／等一下」就打斷。用喇叭時同音異字的回音可能誤觸插話，戴耳機最準。念完 2.5 秒內與剛念內容相同的長句會被忽略。語音模式只用模擬的語音 API（含模擬喇叭回音）做過自動化測試，麥克風與喇叭未在實機驗證。
- 鏡頭互動依 docs/11 實作在場、面向、停止手勢與手臂指向（未經實機驗證，未做雙目校正）；不做眼睛視線。沒有記憶與知識層。
- 鏡頭畫面與鏡頭設定的自動化測試用假鏡頭與假模型（啟動／關閉不重複回報、載入中或播放中關閉不留下模型與舊畫面）；兩格畫面的顯示與左右眼差異已在 Chromium 以真實 MediaPipe 播放合成的雙目影像檢查（`docs/validation/camera-preview-2026-10-21.md`），**未在 AR0144 實機上驗證**；每幀多三次縮小繪圖的負擔尚未量測。
- `NOUS_CAMERA` 決定頁面是否允許使用鏡頭，改了要重新啟動核心；設定畫面的「鏡頭」開關只能在已允許時開關鏡頭。安裝項目（鏡頭名稱、左右眼順序、螢幕寬度、鏡頭偏移）只能在 `.env` 改。
- 關閉手掌停止只是不理會手勢，手勢模型仍每幀執行，不會省下 CPU。
- 桌面 App 和瀏覽器分頁同時開著時，兩邊都會嘗試開鏡頭。
- 即時語音的 ChatGPT 方案路徑（gpt-live-1-codex）只用假的 chatgpt.com、sideband 與頁面測過，未在真實帳號驗證；它依賴未公開文件的端點與 alpha 標頭，OpenAI 改格式時會在開始時照實報錯（自動模式改用 API key 並告知）。這條路徑沒有 MCP，Esc 只能靜音不能取消回覆，交辦最長等 187 秒（計算見驗證文件）。
- Agent 工具：即時語音可上網查詢（web_search）；遠端 MCP 只在 API key 路徑；背景任務與文字對話在引擎支援時可上網搜尋（不支援時自動改回不帶工具並標示缺口）。讀寫本機檔案尚未提供；外部副作用的完整 Action Gate 尚未實作，目前 MCP 需核准的動作以確認卡＋語音固定語句逐次確認。
- 家電控制一次一台，不支援房間指令；冷氣只支援 AIFA 冷氣，紅外線家電只能一次按一個鍵，兩者都沒有回讀，只會說「已送出，請確認」；不是 AIFA 的冷氣與無線按鈕不支援。家電查詢與控制只在即時語音模式（ChatGPT 方案或 API key 路徑）提供，瀏覽器語音辨識與文字對話沒有這兩個工具。
- 單一使用者、單一螢幕；資料以明文 JSON 存在本機。

## 與正式規格的關係

本原型依使用者要求建立於獨立資料夾，借用 06／07 的 Shell 狀態、`visibility_reason` 與 Task 狀態概念，但**沒有**照 07 §2 的 monorepo 結構，也沒有 `packages/shared/schemas` 的版本化 JSON Schema（型別標為 `proto-0.1`）。正式實作仍從 08 的 PR-00 開始；本原型可作為 PR-01／PR-02 的視覺與互動參考。
